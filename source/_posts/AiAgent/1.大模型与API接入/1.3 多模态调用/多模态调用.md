## 1.3 多模态调用
### 1.3.1 视觉理解（图生文）
支持图片输入的典型调用（OpenAI 格式）：

#### 单图调用
```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "描述这张图片"},
            {"type": "image_url", "image_url": {
                "url": "https://example.com/img.jpg",  # 公网URL
                # "url": f"data:image/jpeg;base64,{base64_str}"  # base64
                "detail": "auto"  # auto / low / high
            }}
        ]
    }]
)
```

- detail 参数：low（廉价，固定85 token）、high（精细裁剪，按图大小计费）、auto（默认，自动选择）。
- 图片上传方式：公网URL 或 base64 编码。本地图片推荐 base64 内联，避免额外文件服务。

#### 多图处理
多模态模型天然支持在一次请求中传入多张图片，只需在 content 数组中放置多个 image_url 块即可。

**同时分析多张图片**：
```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "比较这两张UI截图的差异，生成修改清单"},
            {"type": "image_url", "image_url": {"url": "https://example.com/ui_before.png"}},
            {"type": "image_url", "image_url": {"url": "https://example.com/ui_after.png"}}
        ]
    }]
)
```

**多图对话（交替图片与文字）：**

```python
content = [
    {"type": "text", "text": "第一步：分析这张架构图"},
    {"type": "image_url", "image_url": {"url": "url1"}},
    {"type": "text", "text": "架构图中的数据库选型是否合理？"},
    # 模型在此回复...
    {"type": "text", "text": "第二步：对比这张实际部署图"},
    {"type": "image_url", "image_url": {"url": "url2"}},
    {"type": "text", "text": "两张图有哪些不一致？"}
]
```
多图处理注意事项：

| 关注点 | 说明 |
| -- | -- |
| 图片数量限制 | 取决于模型上下文窗口，单次请求建议不超过 10 张，总 token 需留足文本回复空间 |
| 图片顺序有意义 | 模型按图片出现顺序理解，第一张是“图1”，第二张是“图2” |
| 标签/箭头辅助 | 可在图片上标注编号或箭头，配合文字说明“右上角红色框区域”效果更好 |
| 分辨率控制 | detail: low 可大幅降低成本，适合不需要精细视觉的对比任务 |
| Token 消耗 | 一张 1024×1024 的 high 图约消耗 765 token，多图成本会叠加 |
| 避免过载 | 过多图片会让模型注意力分散，建议每轮聚焦 1-3 张核心图片 |


Agent 中的典型应用：

- UI 自动化：截图当前界面 → 多模态模型分析布局 → 生成操作指令
- 文档审核：上传合同扫描件 + 标准模板 → 对比差异点
- 监控告警：异常图表 + 历史基线图 → 分析趋势变化

### 1.3.2 视频理解
GPT-4o、Gemini 1.5 Pro 支持视频输入。本质是将视频抽帧为图片序列后输入模型，并非原生“理解视频流”。

OpenAI 方式（抽帧后按图片处理）：
```python
import base64
import cv2

def video_to_frames(video_path, frame_interval=30):
    """每 frame_interval 帧抽取一帧，返回 base64 列表"""
    frames = []
    cap = cv2.VideoCapture(video_path)
    frame_count = 0
    while True:
        ret, frame = cap.read()
        if not ret:
            break
        if frame_count % frame_interval == 0:
            _, buffer = cv2.imencode(".jpg", frame)
            b64 = base64.b64encode(buffer).decode("utf-8")
            frames.append(f"data:image/jpeg;base64,{b64}")
        frame_count += 1
    cap.release()
    return frames

frames = video_to_frames("demo.mp4", frame_interval=30)
content = [{"type": "text", "text": "总结这个视频的内容"}]
for f in frames[:10]:  # 控制帧数，避免 token 爆炸
    content.append({"type": "image_url", "image_url": {"url": f, "detail": "low"}})

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": content}]
)
```
Gemini 方式（直接传入视频文件）：

```python
import google.generativeai as genai

model = genai.GenerativeModel("gemini-1.5-pro")
video_file = genai.upload_file("demo.mp4")  # 自动处理抽帧

response = model.generate_content([video_file, "总结视频内容"])
```

注意事项：
- 抽帧间隔需根据视频长度调整，短视频（<1分钟）可每秒1帧，长视频需加大间隔
- 当前模型通常只理解视觉+时序，不包含音频轨（需单独用 Whisper 提取音频文字后一并传入）
- 视频理解的 Token 消耗极高，生产环境中需做帧数上限和分辨率限制

### 1.3.3 语音接口概述

**语音转文字（Whisper）**：

```python
audio_file = open("speech.mp3", "rb")
transcript = client.audio.transcriptions.create(
    model="whisper-1", file=audio_file
)
print(transcript.text)
```
- 支持格式：mp3, wav, m4a, webm 等
- 文件大小限制：25MB
- 支持多语言自动识别


**文字转语音（TTS）**：

```python
response = client.audio.speech.create(
    model="tts-1",           # tts-1 快/便宜，tts-1-hd 高质量
    voice="alloy",           # alloy/echo/fable/onyx/nova/shimmer
    input="你好，我是Agent助手"
)
response.stream_to_file("output.mp3")
```
- 六种音色可选
- 支持多语言，自动适配输入语言
- 流式输出需用 stream 参数

在 Agent 中，语音接口通常用于语音控制、语音交互、多模态输入输出。



### 1.3.4 多模态通用注意事项（新增）

｜ 关注点 ｜ 说明｜
｜ -- ｜ -- ｜
｜ 成本 ｜ 多模态输入 Token 消耗远大于纯文本，图片/视频需评估 ROI ｜
｜ 模型兼容性 ｜ GPT-4o 支持图文混合，GPT-4o-mini 也支持但效果略差；Claude 3.5 图文皆可 ｜
｜ 隐私合规 ｜ 图片/音频包含敏感信息时，确认 API 服务商的隐私政策，或使用本地模型 ｜
｜ 错误处理 ｜ 无效图片/格式不支持会直接报错，需做文件校验 + try-catch ｜
｜ 上下文窗口 ｜ 多图+多轮对话极易撑爆窗口，务必计算 Token 并做截断 ｜
｜ 幻觉依旧存在 ｜ 多模态模型同样会“看图说话”编造内容，关键场景需人工复核 ｜
