## 10.2 自动化技术文章生成器

### 项目定位

输入一个主题，多个 Agent 协作完成「检索资料 → 撰写初稿 → 审核把关 → 排版输出」的全流程，产出可直接发布的技术文章。是多 Agent 协作的练兵场。

### 多 Agent 角色设计

```
[检索 Agent]  调用搜索 API + 读技术文档，整理素材要点
     ↓
[撰写 Agent]  基于素材起草文章（结构+正文+代码示例）
     ↓
[审核 Agent]  检查技术准确性、逻辑、格式，提出修改意见
     ↓
[排版 Agent]  转 Markdown、加标题层级、补代码高亮
```

采用层级管理 + 流水线组合（见 6.1），Manager 负责派发与汇总。

### 工具

- 搜索 API（如 SerpAPI / Bing）获取最新资料；
- 代码解释器：验证文中示例代码能否运行；
- 文件读写：落盘草稿与终稿。

### 关键实现点

1. **任务拆解**：Manager 把「写 Kubernetes 入门」拆成「概念→架构→部署→示例」四块，分别派给撰写 Agent；
2. **审校闭环**：审核 Agent 返回 `{"pass": false, "issues": [...]}` 时，撰写 Agent 按意见修订，最多循环 3 轮；
3. **防幻觉**：要求所有技术论断必须引用检索素材，无来源论断打回重查。

### 难点与解法

- 多 Agent 成本高 → 检索/审校用便宜小模型，仅撰写用大模型；
- 风格不稳定 → 给撰写 Agent 固定「文风示例」few-shot；
- 循环不收敛 → 设最大修订轮次 + 强制输出。

### 收获

实战多 Agent 协作模式、任务编排、工具封装、成本控制，是体现「工程化思维」的进阶作品。
