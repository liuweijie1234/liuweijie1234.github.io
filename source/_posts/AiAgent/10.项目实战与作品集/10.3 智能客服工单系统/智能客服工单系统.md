## 10.3 智能客服工单系统

### 项目定位

面向企业的客服 Agent：先识别用户意图，再调用业务工具（查订单、退换货），解决不了平滑转人工。是「Agent + 业务系统 + 安全合规」的综合实战。

### 核心模块

- **意图识别与路由**：分类（咨询/退款/投诉/其他）→ 路由到对应处理链；
- **业务工具调用**：`query_order`（查订单）、`create_refund`（建退款单）、`check_logistics`（查物流）；
- **升级人工节点**：置信度低或高危操作 → 转人工并附上上下文摘要。

### 技术要点

1. **结构化意图**：用 Structured Output 强制输出 `{intent: enum, confidence: float}`，路由稳定；
2. **工具权限分级**：查订单（只读低危）自动执行；退款（高危）必须人工确认（见 9.2）；
3. **数据隔离**：RAG 知识库按 `dept` 过滤，不同客服号只看对应业务文档（见 9.3）；
4. **可观测**：每次会话记录工具调用链 + 审计日志，便于复盘与合规。

### 关键代码片段（意图路由）

```python
class Intent(BaseModel):
    intent: str = Field(enum=["咨询","退款","投诉","其他"])
    confidence: float

resp = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[...],
    response_format=Intent,
)
route_to_handler(resp.choices[0].message.parsed.intent)
```

### 难点与解法

- 误退款风险 → 高危工具 Human-in-the-loop + 双重校验；
- 用户表述模糊 → 主动追问澄清（Few-shot 引导）；
- 知识陈旧 → 业务 FAQ 走 RAG 实时更新，不写死在提示词。

### 收获

最能体现「生产级 Agent」素养的项目：业务集成、权限审计、安全合规、人工兜底一个不落，面试含金量高。
