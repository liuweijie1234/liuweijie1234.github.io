# 思维链（Chain-of-Thought, CoT）

不要只问“答案是什么”，要问“你是怎么想的，一步一步写出来”。

## 一、什么是思维链
思维链（Chain-of-Thought，简称 CoT）是一种提示词技术，要求模型在给出最终答案之前，**先输出中间推理步骤**。这些步骤就像人类解题时的草稿纸，显式地记录了从问题到答案的思考过程。

**零样本 vs 思维链的对比**：

｜ 方式 ｜ 示例提示词 ｜ 模型行为 ｜
｜ -- ｜ -- ｜ -- ｜
｜ 标准提示 ｜ 123 * 456 = ? ｜ 直接输出答案（容易错） ｜
｜ 思维链提示 ｜ 123 * 456 = ? 一步一步思考。 ｜ 输出：123×400=49200，123×50=6150， 123×6=738，总和=49200+6150+738=56088 ｜

对于复杂推理任务（数学、逻辑、多步规划），思维链能显著提升准确率，而且让模型的思考过程可审查、可调试。

## 二、为什么思维链对 Agent 至关重要

在 AI Agent 的开发中，推理过程不是可选项，而是必需品。原因有三个：

1. Agent 需要制定计划：用户说“帮我安排下周的北京出差行程”，模型不能直接调用订票 API，而要先规划出“查日历→查航班→查酒店→比较→预订”这样的步骤链。

2. 工具调用需要顺序：ReAct 模式本质上就是一种 CoT——模型先“思考”该用什么工具、传入什么参数，然后“行动”，再根据“观察”结果进一步思考。

3、 错误可追溯：当 Agent 做出错误决策时，如果只能看到最终动作（调了一个不存在的 API），你无从下手；但如果有完整的推理链，你就能定位到哪一步的推理出了问题。

## 三、思维链的几种形式

### 1. Zero-shot CoT（零样本思维链）

在提示词末尾加上一句“让我们一步一步思考”（Let's think step by step），就能激发模型输出推理过程。这是成本最低、最通用的 CoT 方式。

```text
用户问题：一个长方体水箱，长3米、宽2米、高1.5米，现在水位是0.8米，请问水箱里有多少立方米的水？
让我们一步一步思考。
```
模型会自行分解步骤：

```text
1. 确定计算目标：求水的体积
2. 水的体积 = 长 × 宽 × 水位高度
3. 代入数值：3 × 2 × 0.8 = 4.8
4. 所以，水的体积是 4.8 立方米。
```
适用场景：通用推理、简单规划、不需要特定领域格式的任务。

### 2. Few-shot CoT（少样本思维链）

提供 1~3 个“问题→推理链→答案”的完整示例，然后要求模型按照同样的推理风格处理新问题。这种方式可以同时控制推理格式和推理深度。

```text
示例：
问：一个三角形的底是10cm，高是6cm，面积是多少？
推理：三角形面积 = (底 × 高) ÷ 2。底是10，高是6，所以面积 = (10×6)÷2 = 30。
答：30平方厘米。

问：一个圆的半径是7cm，周长是多少？
推理：圆的周长 = 2 × π × 半径。π取3.14，半径是7，所以周长 = 2×3.14×7 = 43.96。
答：43.96厘米。

现在请回答：
问：梯形的上底3cm、下底5cm、高4cm，面积是多少？
```
通过示例，模型学会了“先写公式，再代入，最后给答案”的结构。这种方式在 **Agent 工具调用**中非常常用——给出 1-2 个“思考→行动→观察”的完整对话轨迹，模型就能稳定复现类似行为。

### 3. 结构化思维链（Structured CoT）

在 Agent 开发中，我们经常需要模型按照固定格式输出推理步骤，例如：

```text
Thought: 我需要先查用户账户状态
Action: query_account(user_id=12345)
Observation: 账户状态为“已冻结”
Thought: 账户被冻结无法执行转账，我需要告知用户并建议联系客服
Final Answer: 您的账户当前处于冻结状态，无法完成转账。请致电客服热线解冻账户。
```
这种结构化思维链使得我们可以：

- 用正则或 JSON 解析每一步的 Action 和参数
- 自动执行工具调用
- 将 Observation 注入回对话，形成自动循环

**核心原则**：推理链的结构一旦确定，就必须在所有示例中保持完全一致，否则模型会随机选择格式，导致解析失败。

## 四、思维链在 Agent 工作流中的位置

在一个典型的 ReAct Agent 中，每一轮推理就是一条思维链中的一个步骤：

```
graph LR
    U[用户问题] --> T1[Thought 1: 分析需求]
    T1 --> A1[Action 1: 调用工具A]
    A1 --> O1[Observation 1: 工具A返回]
    O1 --> T2[Thought 2: 整合信息]
    T2 --> A2[Action 2: 调用工具B]
    A2 --> O2[Observation 2: 工具B返回]
    O2 --> T3[Thought 3: 形成最终答案]
    T3 --> F[Final Answer]
```

Agent 的执行循环就是不断生成 **Thought-Action-Observation** 三元组，直到模型认为信息足够输出 `Final Answer`。

对于全栈开发者，可以把这个循环理解为一个状态机：

- State 包含对话历史、工具返回结果
- Transitions 由模型的 Thought 决定（选择哪个工具，什么参数）
- 终止条件是模型输出 Final Answer

## 五、Agent 提示词中的思维链模板

以下是一个实际可用的 Agent 系统提示词，融合了角色、工具描述、以及结构化的思维链格式：

```text
你是一个智能助手，可以调用以下工具：
- calculator(expression): 计算数学表达式，返回数值结果。
- search(query): 在知识库中搜索信息，返回匹配的文本片段。

请严格按照以下格式响应：

用户输入后，你需要这样思考并行动：
Thought: 你的推理过程，分析现在需要做什么，为什么。
Action: 要调用的工具名称和参数，格式如 tool_name(param1=value1, ...)
Observation: 工具返回的结果（这个由系统自动填入，你只需要在下一轮里引用）
...（Thought/Action/Observation 可重复多次）...
Thought: 我现在已经有了足够的信息来回答用户的问题。
Final Answer: 用自然语言回复用户，基于所有的观察结果。

开始！
用户：帮我算一下 325 × 17 的结果，然后告诉我这个数字在百科里有没有特殊含义。
```

这个模板就是思维链在 Agent 中的最直接落地。模型会像填空一样，在 Thought: 和 Action: 后面输出自己的推理和选择。

## 六、常见陷阱与优化

| 陷阱 | 表现 | 解决方案 |
| -- | -- | -- |
| 推理链过于简短 | 模型直接跳到 Final Answer，跳过必要工具调用 | 在提示词中强制要求至少一轮 Thought，或提供更完整的 few-shot 示例 |
| 推理链天马行空 | 模型开始讨论与任务无关的“哲学思考” | 在系统提示中添加“只思考解决用户问题所需步骤”的约束 |
| 格式漂移 | 前几轮格式正确，后面开始丢失 Action 标签 | 在每轮 Observation 之后重新注入格式提示（通常框架会自动做） |
| 虚假推理 | 推理过程看起来合理，但结论错误（内部逻辑跳跃） | 让模型在 Thought 中把判断依据写清楚，“为什么选择这个工具而不是另一个” |
| 过长的推理链消耗过多 Token | 简单问题也要五六步 | 根据任务复杂度动态选择是否开启 CoT，简单任务用零样本直出 |

## 七、思维链与其他提示词技术的关系

- **Few-shot** 是提供“样板”，CoT 是让模型在样板中展示“思考过程”。两者通常结合使用（Few-shot CoT）。
- **ReAct** 是 CoT 的一个特化版本，把推理步骤聚焦在 工具选择与信息整合 上。
- **Self-Consistency（自洽性）** 是 CoT 的增强：让模型跑多次 CoT，取多数投票答案，可以进一步提升推理准确率（2.3 节会详细展开）。

## 八、小结
思维链本质上就是把模型的隐性推理显性化。对于 Agent 开发者，它不仅是提升准确率的手段，更是调试和优化 Agent 行为的核心窗口。

你现在可以这样做练习：

1. 挑一个需要两步以上推理的任务（比如“查询今天天气，如果下雨就提醒带伞”）。
2. 先用零样本 CoT（加一句“让我们一步一步思考”）看模型输出什么。
3. 再改用结构化 CoT 格式，看模型是否按 Thought/Action 格式走。
4. 对比两者的可解析性和准确性。
