## 2.2 结构化输出：解析容错与异常处理

就算用了 JSON Mode / Structured Output，线上依然会碰到解析失败。因为：

- 老模型或不支持的厂商可能「假装支持」实则输出残缺 JSON；
- 模型偶尔在 JSON 前后多说一句废话（如「好的，这是结果：{...}」）；
- 流式输出中途被打断，JSON 没写完。

所以「解析层容错」是生产级 Agent 的必写代码。

### 1. 去掉 JSON 前后的噪声

```python
import re, json

def extract_json(text: str):
    text = text.strip()
    # 优先找 ```json ... ``` 代码块
    m = re.search(r"```json\s*(.*?)\s*```", text, re.DOTALL)
    if m:
        text = m.group(1)
    # 再找第一个 { 到最后一个 } 之间的内容
    start, end = text.find("{"), text.rfind("}")
    if start != -1 and end != -1:
        text = text[start:end+1]
    return text
```

### 2. 解析失败的三层兜底

```python
def safe_parse(text: str) -> dict | None:
    raw = extract_json(text)
    # 第 1 层：直接解析
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        pass
    # 第 2 层：尝试修复常见错误（尾随逗号、单引号）
    try:
        fixed = raw.replace("'", '"').replace(",}", "}").replace(",]", "]")
        return json.loads(fixed)
    except json.JSONDecodeError:
        pass
    # 第 3 层：交给模型修复（代价高，少用）
    return None
```

### 3. 字段校验：别信任模型的输出

即使 JSON 合法，字段也可能缺失或类型错。用 Pydantic 兜底最省心：

```python
from pydantic import BaseModel, ValidationError

class Result(BaseModel):
    intent: str
    reply: str

def parse_strict(text):
    data = safe_parse(text)
    if data is None:
        return None
    try:
        return Result(**data)        # 缺字段/类型错会抛异常
    except ValidationError as e:
        print("字段校验失败:", e)
        return None
```

### 4. 整体失败怎么兜底

解析失败不是世界末日，关键是**降级策略**：

- 重试一次（换 temperature 或补一句「请只输出 JSON」）；
- 重试仍失败 → 走默认分支（如转人工、返回「我没听懂」）；
- 记录日志 + 上报监控，方便后续优化提示词。

```python
result = parse_strict(model_output)
if result is None:
    metrics.incr("json_parse_fail")
    return fallback_response()   # 兜底话术 / 转人工
```

### 经验口诀

- 模型输出「先当不可信」，永远做 `try/except` + 字段校验。
- 解析层和服务层解耦：解析只负责「尽力拿到字典」，业务再决定字段怎么用。
- 监控解析失败率，一旦飙升说明提示词或模型变了，要回看。
