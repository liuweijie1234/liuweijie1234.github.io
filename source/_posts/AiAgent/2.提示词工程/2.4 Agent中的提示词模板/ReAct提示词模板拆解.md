## 2.4 Agent 提示词模板：ReAct 模板拆解

ReAct（Reason + Act）是 Agent 最经典的提示词范式。它的精髓是：**让模型在「思考」和「行动」之间交替，并把过程显式写进同一个 prompt**。

### 标准 ReAct 输出格式

```
思考：我需要先查一下北京的天气，才能决定是否建议带伞。
行动：search_weather{"city": "北京"}
观察：北京今日多云，降水概率 60%。

思考：降水概率较高，应该建议带伞。
行动：finish{"answer": "建议带伞，今天北京有60%降水概率。"}
```

三个关键字：`思考(Thought)` / `行动(Action)` / `观察(Observation)`。模型只负责产出「思考」和「行动」，「观察」由你的代码执行工具后回填。

### 模板骨架（可直接套用）

```text
你是一个能使用工具的智能助手。可用工具：
{tools_description}

请严格按照以下循环工作：
1. 先用「思考：」分析当前情况与下一步；
2. 再用「行动：」选择一个工具并给出 JSON 参数；
3. 等待系统返回「观察：」结果；
4. 重复直到能回答，用「行动：finish{"answer": "..."}」结束。

示例：
思考：用户问北京天气，我需要先查天气。
行动：search_weather{"city":"北京"}
观察：北京多云，降水概率60%
思考：可以回答了。
行动：finish{"answer":"建议带伞。"}

现在开始：
用户问题：{user_question}
思考：
```

### 关键设计点

- **工具描述 `{tools_description}`**：必须写清每个工具的名字、用途、参数（见「工具描述编写规范」）。
- **强制格式**：用「行动：工具名{json}」这种强约定，代码才好解析；不要让它自由发挥。
- **结束信号**：必须约定一个 `finish` / `answer` 动作作为终止，否则循环不会停（配合「超时与死循环防护」）。
- **Few-shot 示例**：给 1~2 个完整循环示例，模型的格式遵循度会大幅提升。

### 常见失效

- 模型只「思考」不「行动」→ 在 prompt 里强调「遇到需要外部信息时必须调用工具」；
- 模型把观察结果当成了自己要生成的 → 明确「观察由系统提供，你只需产出思考和行动」；
- 模型一次输出多个行动 → 限定「每轮只输出一个行动，等观察后再继续」。
