## 2.4 Agent 提示词模板：动态组装策略

生产环境的 Agent 提示词**不是写死的一段字符串**，而是在运行时「拼」出来的。因为不同用户、不同任务需要的上下文完全不同。

### 一个 Agent System Prompt 的构成

```
[固定部分] 角色设定 + 全局规则 + 输出格式约定
[动态部分1] 工具列表（根据当前可用工具拼入）
[动态部分2] 用户画像 / 历史偏好（长期记忆）
[动态部分3] 最近 N 轮对话（短期记忆）
[动态部分4] 本次检索到的知识片段（RAG 上下文）
[动态部分5] 当前任务状态 / 子目标（工作记忆）
```

### 组装代码示例

```python
def build_system_prompt(user, tools, history, memory, docs):
    parts = []
    parts.append(ROLE_TEMPLATE)                 # 固定角色
    parts.append(format_tools(tools))           # 动态工具
    if memory:
        parts.append(format_memory(memory))     # 动态长期记忆
    parts.append(format_history(history))       # 动态短期记忆
    if docs:
        parts.append(format_docs(docs))         # 动态知识
    return "\n\n".join(parts)
```

### 组装原则

1. **固定与动态分离**：把不常变的放模板文件，常变的放函数参数，避免一个大字符串难维护。
2. **上下文预算意识**：模型窗口有限，动态部分要按「优先级 + 截断」拼。优先级通常是：当前工具 > 当前任务状态 > 检索知识 > 长期记忆 > 历史对话。
3. **明确边界标记**：用清晰的分隔符（如 `### 可用工具 ###`）隔开各块，防止模型把「知识」误当成「指令」（防范 Prompt 注入）。
4. **可观测**：把最终拼好的完整 prompt 落日志，出问题能复现、能 debug。

### 进阶：分层与缓存

- **分层 prompt**：把「系统指令层」和「数据上下文层」分开管理，数据层频繁变、指令层 rarely 变。
- **前缀缓存（Prefix Cache）**：指令层不变的部分可让推理服务缓存 KV，显著降低延迟和成本（见「框架内部机制剖析 / Token 缓存」）。

### 反模式

- 把所有东西塞进一个超长字符串，改一处牵全身；
- 动态内容不做长度限制，导致 token 暴涨、成本失控；
- 把不可信的检索内容拼接时不加标记，埋下注入隐患。
