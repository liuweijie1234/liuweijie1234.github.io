## 3.1 数据预处理管道

RAG 效果的上限，往往在「喂给模型之前」就已经被决定了。预处理管道（Pipeline）做不好，后面再强的模型也救不回来。

### 完整管道一览

```
原始文档(PDF/Word/网页/表格)
   ↓ 解析(Parse)
纯文本 + 结构(标题/段落/表格)
   ↓ 清洗(Clean)
去页眉页脚、冗余空白、乱码
   ↓ 分块(Chunk)
语义完整的片段
   ↓ 元数据采集(Metadata)
来源、章节、时间、权限标签
   ↓ 嵌入(Embed)
向量存入向量库
```

### 1. 文档解析

不同格式坑不同：

- **PDF**：最麻烦，扫描件需 OCR（PaddleOCR / 百度 OCR），文本型 PDF 用 `pdfplumber` / `PyMuPDF` 提取，注意保留标题层级。
- **Word / Markdown**：结构清晰，`python-docx` 直接读段落。
- **HTML 网页**：`BeautifulSoup` / `readability` 去导航栏广告，留正文。
- **表格 / Excel**：`pandas` 读取，转成「字段名: 值」的描述性文本，模型才读得懂。

小白建议：先用 `Markdown` / `txt` 跑通全链路，再攻克 PDF。

### 2. 清洗要点

- 去页眉页脚、页码、版权声明；
- 合并被换行打断的句子；
- 统一全角半角、去除控制字符；
- 保留标题层级，利于后续「按章节」切割。

### 3. 分块（Chunking）

分块是 RAG 最关键的超参数之一，详见「检索策略」，这里先讲原则：

- 块太大 → 噪声多、检索不精准、浪费 token；
- 块太小 → 语义不完整、上下文割裂；
- 优先**按语义边界**切（标题、段落、句号），而不是机械按字数。

### 4. 元数据采集与维护

元数据是「精准检索」的隐藏武器：

| 元数据 | 用途 |
| -- | -- |
| source / 文件路径 | 答案溯源、引用展示 |
| 章节标题 | 混合检索时加权 |
| 更新时间 | 时效加权、过期过滤 |
| 权限标签(dept) | 数据隔离、按角色过滤 |

维护建议：分块时就把元数据一起写入向量库，检索时用元数据过滤（如「只查 2024 年 + 财务部文档」），能极大降低幻觉。

### 经验口诀

- 解析保结构、清洗保干净、分块保语义、元数据保可溯。
- 预处理多花 1 天，RAG 效果能少调 1 周。
