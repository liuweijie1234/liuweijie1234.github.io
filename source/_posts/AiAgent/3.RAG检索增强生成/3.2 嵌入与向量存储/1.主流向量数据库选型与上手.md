## 3.2 嵌入与向量存储：主流向量数据库选型与上手

### 先理清：Embedding 模型和向量库是两回事

- **Embedding 模型**：把文本变成一串数字向量（如 1536 维）。代表：`text-embedding-3-small`、BGE 系列、M3E。
- **向量数据库**：负责存这些向量，并提供「给定查询向量，找出最相似的 N 个」的检索能力。

### 选型速查（按场景）

| 数据库 | 特点 | 适合场景 |
| -- | -- | -- |
| Chroma | 轻量、纯 Python、内存/本地文件 | 入门、原型、单机 |
| FAISS | Facebook 出品，性能好、纯向量索引 | 离线批量、嵌入研究 |
| Qdrant | Rust 写，性能强，有过滤 | 中大型生产 |
| Milvus | 分布式、海量规模 | 企业级、十亿级向量 |
| Weaviate | 内置向量化、混合检索 | 一体化方案 |
| PGVector | 跑在 PostgreSQL 里 | 已有 PG、不想多维护一套 |
| Pinecone | 全托管云服务 | 不想运维、快速上线 |

小白建议：用 **Chroma** 几行代码跑通完整 RAG：

```python
import chromadb
client = chromadb.Client()
col = client.create_collection("docs")

col.add(
    documents=["Agent 是能调用工具的智能体", "RAG 用外部知识增强生成"],
    ids=["1", "2"]
)
hits = col.query(query_texts=["什么是Agent"], n_results=1)
print(hits["documents"])
```

生产常用 **Qdrant / Milvus**，云服务可上 **Pinecone**。如果业务系统本就用 PostgreSQL，直接上 **PGVector** 最省事。

### 索引与更新策略

- 增量写入：新文档来就 `upsert`，别全量重建（慢且贵）。
- 版本管理：文档更新时同步更新对应 chunk 的向量与元数据。
- 过期清理：按 `更新时间` 元数据定期淘汰，避免知识陈旧。

### 选型决策树

1. 只是学习 / demo → Chroma
2. 单机生产、数据量中等 → Qdrant
3. 超大规模、需分布式 → Milvus
4. 已有 PG 不想引入新组件 → PGVector
5. 完全不想运维 → Pinecone
