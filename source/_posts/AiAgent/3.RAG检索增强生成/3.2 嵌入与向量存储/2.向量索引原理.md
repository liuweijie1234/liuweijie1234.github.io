## 3.2 嵌入与向量存储：向量索引原理

为什么向量库能「秒级」从百万向量里找出最相似的几个？靠的是**近似最近邻（ANN）索引**，而非暴力挨个算距离。

### 核心问题：相似度怎么算

嵌入向量之间用**余弦相似度**（最常用）或欧氏距离衡量接近程度：

```
cos(A, B) = (A·B) / (|A| × |B|)
```

值越接近 1，语义越相似。

### 暴力检索的瓶颈

有 100 万条向量，每次查询都要算 100 万次相似度 → 慢且贵。所以需要索引来「缩小搜索范围」。

### 主流索引算法（了解即可）

- **IVF（倒排文件）**：先把向量聚类成很多「桶」，查询时只进最近的几个桶搜。用 `nprobe` 控制查几个桶——查得多更准但更慢。
- **HNSW（分层可导航小世界图）**：构建多层图，查询像「坐电梯到顶层再逐层下行」快速逼近目标。速度快、召回高，是当前最主流的选择（Qdrant/Milvus/Weaviate 默认都用它）。
- **PQ（乘积量化）**：把高维向量压缩存储，省内存，代价是精度略降。

### 在代码里怎么体现

以 Chroma 为例，默认就用 HNSW，你一般不用管；Milvus 创建集合时可指定：

```python
# Milvus 示意：指定索引类型与相似度度量
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 8, "efConstruction": 200}
}
```

### 调优直觉

- `efConstruction`（建索引时）/ `ef`（查询时）越大 → 越准越慢；
- 召回率（Recall）和延迟（Latency）永远是 trade-off，按业务容忍度调；
- 数据量小（几万以内）时，暴力检索和 ANN 差别不大，别过度优化。

### 一句话

向量索引就是「用一点点精度换海量速度」的近似算法，**HNSW 是当前事实标准**，理解它「图搜索」的直觉即可，具体参数交给默认配置。
