## 3.2 嵌入与向量存储：混合检索与元数据过滤

只用「向量语义检索」常常不够——它擅长理解语义，却对**确切关键词、专有名词、编号**无感（搜「GPT-4o」可能给你语义相近但不是它的文档）。

### 混合检索（Hybrid Search）

把两种检索融合：

- **稠密检索（Dense）**：Embedding 向量相似度，懂语义、容错强。
- **稀疏检索（Sparse）**：传统关键词匹配，如 **BM25**，对精确词、术语、编号极其精准。

融合方式：各召回 Top-K，再按分数加权合并（RRF 倒数排名融合是常用手法）。

```python
# 伪代码：混合检索
dense_hits = vector_db.search(query_vec, top_k=10)   # 语义
sparse_hits = bm25.search(query_text, top_k=10)      # 关键词
merged = rrf_fuse(dense_hits, sparse_hits, k=60)     # 倒数排名融合
```

多数向量库（Milvus/Qdrant/Weaviate）已原生支持混合检索，开箱即用。

### 元数据过滤（Metadata Filter）

在向量检索前/后加一层结构化过滤，相当于 SQL 的 `WHERE`：

```python
# 只检索「财务部 + 2024 年之后」的文档
hits = col.query(
    query_texts=["年假政策"],
    n_results=5,
    where={"department": "finance", "year": {"$gte": 2024}}
)
```

典型用法：

- **权限隔离**：`WHERE dept = 当前用户部门`，不同人看到不同文档（见「数据隐私」）。
- **时效加权**：过滤掉过期文档，或对最近文档提权。
- **来源限定**：只查「官方手册」而非「论坛讨论」。

### 两者结合的价值

- 混合检索解决「语义 vs 关键词」的偏科；
- 元数据过滤解决「范围/权限/时效」的精准圈定；
- 二者叠加，是生产级 RAG 召回质量的标配组合。

### 经验

- 专有名词多、术语强的场景（法律/医疗/代码），混合检索提升尤其明显；
- 元数据过滤要「早做」：能在检索前用 `where` 缩小范围的，别等召回后再筛，省算力也提准。
