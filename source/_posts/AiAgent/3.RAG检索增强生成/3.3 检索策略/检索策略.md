## 3.3 检索策略

检索是 RAG 的「第一道关口」，召回质量直接决定生成质量。先有对的块，才有对的答案。

### 稠密 vs 稀疏检索

- **稠密检索（Dense）**：文本 → Embedding → 向量相似度。能理解「同义改写」，如查「怎么退款」能召回「退货流程」。
- **稀疏检索（Sparse，如 BM25）**：基于词频的关键词匹配。对精确词、编号、术语极其精准，但不懂同义。

两者互补，详见「混合检索与元数据过滤」。

### 分块策略（Chunking）

| 策略 | 做法 | 适合 |
| -- | -- | -- |
| 固定长度切分 | 按字数（如 500 字）+ 重叠 | 通用、简单 |
| 递归字符切分 | 按 `\n\n` → `\n` → 句号 递归 | 多数长文 |
| 语义切分 | 按语义边界 / embedding 距离 | 概念密集文档 |
| 按结构切分 | 按标题层级、Markdown 标题 | 技术手册、API 文档 |
| 父子块（Parent-Child） | 检索用小块，生成用大块 | 兼顾精准与上下文 |

**父子文档（Parent Document）** 是实战高频技巧：先用小块做精准检索定位，召回后把它的「父级大块」一起喂给模型，既有命中精度又有完整上下文。

### 多路召回与融合

- 一路检索容易漏，用多路（不同分块大小 / 不同 embedding 模型 / 语义+关键词）各召回一批；
- 再用 **Reranker** 统一精排（见「重排序 Reranker」）；
- 或 RRF 倒数排名融合合并结果。

### 检索参数调优

- `top_k`：召回几条？太少漏信息，太多引入噪声（常用 3~8）。
- 重叠窗口（overlap）：相邻块重叠一部分（如 50 字），避免一句话被切断。
- 阈值过滤：相似度低于某值的直接丢弃，避免「硬凑」。

### 经验口诀

- 先定分块策略，再定召回路数，最后上 Reranker 精排，逐级提召回。
- 不知道怎么切时，从「递归字符切分 + 重叠 + 父子块」起步，最稳。
