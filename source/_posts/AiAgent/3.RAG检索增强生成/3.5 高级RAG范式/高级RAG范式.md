## 3.5 高级 RAG 范式

基础 RAG（检索→生成）在复杂场景下会乏力，于是演化出多种进阶范式。

### 1. Self-RAG（自我反思 RAG）

传统 RAG 无脑检索，Self-RAG 让模型**自己决定要不要检索、检索得够不够、答案靠不靠谱**：

- 模型先判断「这个问题需要检索吗？」；
- 检索后判断「这些资料相关吗？够吗？不够再检索」；
- 生成时给每个论断打「可信度」标记。

价值：省 token（不必事事检索）、提质量（按需多次检索）、可解释（带反思标记）。
实现思路：在提示词里加入 `Retrieve / IsREL / IsSUP / IsUSE` 等特殊决策指令，由模型自省。

### 2. Graph RAG（图检索增强）

把知识建构成**知识图谱**（实体-关系-实体），检索时沿图遍历，适合多跳推理：

- 问「A 公司的竞争对手的供应商是谁」这类需串联多段关系的问题，纯向量检索很难答；
- Graph RAG 先抽取实体关系建图，再图遍历 + LLM 汇总。

代表：微软 GraphRAG。代价是构建图谱成本高，适合知识关系复杂、需全局洞察（如「整个行业的主要玩家有哪些」）的场景。

### 3. Agent 驱动的主动 RAG

把 RAG 当作 Agent 的一个工具，由 Agent **自主决定检索策略**：

- 先规划要查什么；
- 可能多次、多角度检索（如先查概念再查案例）；
- 根据中间结果决定「还要不要补查」。

这是 RAG 与 Agent 能力的融合，对应「Agent核心组件 / 规划」与「工具使用」。

### 4. 其他常见范式

- **Query 改写 / 多查询**：把用户问题改写成更利于检索的多个子问题（HyDE 即「假设性文档嵌入」：先让模型生成理想答案，再用它做向量检索，缓解词汇 mismatch）。
- **层次化 RAG（RAPTOR）**：先把文档聚合成摘要树，检索时既看细节也看高层摘要。
- **CRAG（校正 RAG）**：检索后先评估相关性，不合格则触发网页检索等兜底。

### 选型直觉

| 范式 | 解决的核心痛点 | 复杂度 |
| -- | -- | -- |
| 基础 RAG | 知识时效/私有数据 | 低 |
| Self-RAG | 盲目检索、质量不稳定 | 中 |
| Graph RAG | 多跳关系推理 | 高 |
| Agent RAG | 复杂开放任务 | 高 |

小白建议：先把基础 RAG + Reranker 做扎实，遇到具体瓶颈（幻觉多→Self-RAG；关系推理弱→Graph RAG）再按需升级。
