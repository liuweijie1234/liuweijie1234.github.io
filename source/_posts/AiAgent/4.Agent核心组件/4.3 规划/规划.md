## 4.3 规划（Planning）

复杂任务不能直接「一条路走到黑」，Agent 需要先**把大目标拆成可执行的子任务**，再逐步推进。这就是规划组件。

### 1. 任务分解与子目标生成

让模型把复杂任务拆成有序步骤：

```text
任务：帮我策划一次3天的北京家庭游。
请拆解为子任务，每个子任务给出目标：
1. 确定家庭成员偏好与预算
2. 规划每日景点路线
3. 预订住宿与交通
4. 整理行李清单与注意事项
```

常用手法：

- **少样本分解**：给几个「任务→子任务」示例，模型照着拆；
- **思维树（ToT）/ 思维图（GoT）**：不只一条直线，而是探索多条分支再择优；
- 拆得太细会增加步数和 token，拆到「单步可调用工具完成」即可。

### 2. 依赖关系管理

子任务之间常有先后依赖（先订票才能定行程）。需要：

- 识别依赖（A 完成才能做 B）；
- 把依赖状态写进工作记忆（State），每完成一步更新进度；
- 可并行且无依赖的子任务（如「查天气」和「查景点」）可并行执行提效。

### 3. 动态重规划（Replan）

计划赶不上变化。当：

- 某步工具失败且无降级方案；
- 观察结果和预期严重不符（如景点关门）；
- 用户中途改需求；

Agent 应**重新规划剩余步骤**，而不是硬走原路。实现上：在每轮循环里加一个「是否需要重新规划」的判断节点。

### 4. 反思机制（Reflexion）

Reflexion（2023，Shinn 等）让 Agent **从失败中学习**：任务结束后，用 LLM 生成一段「反思」文本，总结这次哪里错了、下次怎么改，把反思存进记忆，下次任务前读入。

```
执行 → 评估（成功/失败）→ 反思（为什么失败）→ 把反思写入 memory → 下次带着反思重来
```

它和 Replan 的区别：Replan 是「中途改路线」，Reflexion 是「事后总结经验、长期变聪明」。

### 经典范式对比

| 范式 | 特点 | 适合 |
| -- | -- | -- |
| ReAct | 边想边干，单线 | 通用、工具型任务 |
| Plan-and-Execute | 先整体规划，再逐步执行 | 步骤多、需宏观把控 |
| Reflexion | 失败后反思、迭代变强 | 需反复试错的任务 |

### 经验

- 简单任务别过度规划，直接 ReAct 更轻；
- 规划结果要可观测（把 plan 展示给用户），便于人工纠偏；
- 重规划和反思是「让 Agent 鲁棒」的关键，生产系统建议都加上。
