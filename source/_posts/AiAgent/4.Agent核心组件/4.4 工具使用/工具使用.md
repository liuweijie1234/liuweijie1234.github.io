## 4.4 工具使用（Tool Use）

工具是 Agent 区别于「纯聊天模型」的关键——它让模型能**动手做事**：查数据库、调 API、跑代码、发消息。

### 1. 函数定义与 JSON Schema 编写

现代大模型通过 **Function Calling** 调用工具：你给模型一份工具清单（含 JSON Schema 参数），模型输出「要调哪个函数 + 什么参数」，由你的代码真正执行。

```json
{
  "name": "get_weather",
  "description": "查询城市天气。当用户问天气、温度、出行建议时调用。",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {"type": "string", "description": "城市名，如 '北京'"},
      "date": {"type": "string", "description": "日期，格式 YYYY-MM-DD"}
    },
    "required": ["city"]
  }
}
```

编写规范见「Agent 提示词模板 / 工具描述编写规范」。

### 2. 工具选择与并行调用

- **选择**：模型根据工具描述和当前问题自己挑。工具太多（>20）选择准确率会降，建议按任务**动态加载**相关工具。
- **并行**：当多个工具互不依赖（如「查北京天气」+「查上海天气」），可一次返回多个调用并行执行，大幅降延迟。

```python
# 伪代码：并行执行模型返回的多工具调用
calls = parse_tool_calls(model_output)   # 可能返回多个
results = await asyncio.gather(*[run_tool(c) for c in calls])
```

### 3. 错误处理与自我修正

工具调用必然失败（超时、参数错、返回异常），Agent 必须能兜底：

- **参数错误**：把报错回灌给模型，让它改参数重试（「city 字段缺失，请补全」）；
- **工具超时/不可用**：降级到备用工具或直接告知用户；
- **返回异常**：校验返回结构，脏数据别直接喂模型；
- **重试上限**：同一工具失败超过 N 次就放弃，转人工或换思路。

```python
for attempt in range(3):
    try:
        return run_tool(call)
    except ToolError as e:
        obs = f"工具执行失败：{e}，请检查参数或换方案"
        # 把 obs 回填，让模型自我修正
```

### 4. 自定义工具开发

两类最常见：

- **API 工具**：封装业务接口（查订单、发短信）。注意鉴权、限流、超时设置。
- **代码解释器（Code Interpreter）**：让模型生成 Python 代码并在沙箱执行，适合数据分析、计算。务必**沙箱隔离**，限制文件/网络/资源，防恶意代码。

```python
def code_interpreter(code: str):
    # 在受限沙箱(docker/限制资源)里执行，超时 10s 强杀
    result = sandbox.run(code, timeout=10)
    return result
```

### 经验口诀

- 工具描述写清楚「何时用 + 返回啥」，选择准确率立升；
- 所有工具调用都要有「失败重试 + 降级 + 超时」三件套；
- 高权限工具（发邮件、退款）必须人类确认（见「权限与审计」）。
