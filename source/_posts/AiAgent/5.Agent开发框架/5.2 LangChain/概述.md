## 5.2 LangChain

LangChain 是最早火起来的 LLM 应用开发框架，提供大量「积木」，让你少写样板代码。

### 核心抽象

- **Model（LLM / ChatModel）**：对接各家大模型。
- **Prompt（提示词模板）**：参数化的提示词，`PromptTemplate` / `ChatPromptTemplate`。
- **Chain（链）**：把「模型 + 提示词 + 其他组件」串成固定流水线（如 `LLMChain`、`RetrievalQA`）。
- **Tool / Toolkit**：给 Agent 用的工具抽象（见「Agent核心组件 / 工具使用」）。
- **Memory（记忆）**：对话历史的存储与读取（见「记忆系统」）。
- **Retriever（检索器）**：RAG 里的召回组件，和向量库对接。
- **Agent / AgentExecutor**：旧版「自动循环调工具」的执行器。

### AgentExecutor 旧模式分析

`AgentExecutor` 是 LangChain 早期跑 ReAct 的方式：你给 Agent（含提示词 + 工具），Executor 负责「调模型→解析行动→执行工具→回填→循环」直到结束。

局限：

- 流程是**写死的循环**，难以加条件分支、人工介入、复杂状态；
- 不利于持久化和回溯；
- 随着需求复杂，越来越难控制。

因此官方现在主推 **LangGraph** 来做复杂 Agent，AgentExecutor 更适合简单 Demo。

### Tool 与 Toolkit 抽象

```python
from langchain.tools import tool

@tool
def search_weather(city: str) -> str:
    """查询城市天气。city: 城市名"""
    return real_api(city)

# 把工具交给 Agent / Graph 使用
```

`@tool` 装饰器会自动从函数签名 + docstring 生成工具描述（description 来自 docstring，所以**写好 docstring 很重要**）。

### 与 LangGraph 的对比选型

| 维度 | LangChain（Chain/AgentExecutor） | LangGraph |
| -- | -- | -- |
| 流程控制 | 固定线性 / 简单循环 | 图结构，支持分支/循环/回溯 |
| 状态管理 | 弱 | 强（State + Checkpointer） |
| 复杂 Agent | 吃力 | 得心应手 |
| 上手成本 | 低，积木多 | 略高，概念多 |

建议：**简单拼接用 LangChain，复杂可控 Agent 用 LangGraph**。两者可混用（LangGraph 里照样能用 LangChain 的 Model/Tool/Retriever）。

### 一句话

LangChain 是「零件工具箱」，适合快速拼简单应用；真正要造生产级 Agent，把它当零件库 + 用 LangGraph 做编排。
