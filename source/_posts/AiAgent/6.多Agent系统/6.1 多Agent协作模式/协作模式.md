## 6.1 多 Agent 协作模式

单 Agent 处理复杂任务容易「顾此失彼」。多 Agent 把任务分给多个专精角色，协作完成。

### 1. 顺序流水线（Pipeline）

A 干完把结果交给 B，B 再交给 C，像工厂流水线。

```
研究员 → 撰写者 → 审核者 → 发布
```

适合步骤清晰、强依赖的任务（如「调研→写稿→校对」）。优点简单可控；缺点是前一步卡住全链路停。

### 2. 辩论式对抗（Debate）

两个 Agent 持不同观点互相辩驳，最终由裁判/汇总者收敛出更优答案。

```
Agent-A(支持) ⇄ Agent-B(反对) → 裁判汇总
```

适合需要多视角、降低偏见、提升推理质量的场景（如方案评审、复杂决策）。代价是通信轮次多、token 高。

### 3. 层级管理（管理者-执行者）

一个 Manager Agent 负责拆解任务、派发给多个 Worker Agent，并汇总结果。

```
        Manager(规划+调度)
       /      |       \
  Worker1  Worker2  Worker3
       \      |       /
        Manager(汇总)
```

最像真实团队，适合大规模、可并行的任务。Manager 本质是「规划 + 工具路由」的 Agent。

### 4. 自由对话（Peer-to-Peer）

多个 Agent 平等对话、自由交换信息，没有中心调度。灵活但**难收敛、难控制**，适合探索型头脑风暴，生产少用。

### 模式对比

| 模式 | 控制性 | 并行度 | 适合 |
| -- | -- | -- | -- |
| 顺序流水线 | 高 | 低 | 步骤强依赖 |
| 辩论对抗 | 中 | 中 | 需多视角/降偏见 |
| 层级管理 | 高 | 高 | 大规模可并行任务 |
| 自由对话 | 低 | 高 | 探索头脑风暴 |

### 经验

- 企业落地**首选层级管理 + 流水线组合**：Manager 控全局，Worker 并行干，关键节点加审核。
- 不是 Agent 越多越好——通信成本随数量指数涨，3~5 个角色通常够用。
- 无论哪种模式，都要有「终止条件」和「汇总机制」，否则永远聊不完。
