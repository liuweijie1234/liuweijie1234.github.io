## 6.2 多 Agent 框架实战

主流多 Agent 框架各有侧重，按需选用。

### 1. CrewAI：角色化协作

CrewAI 把多 Agent 抽象成「**团队（Crew）= 多个角色（Agent）+ 任务（Task）**」，强调像管团队一样管 Agent。

```python
from crewai import Agent, Task, Crew

researcher = Agent(
    role="研究员",
    goal="收集关于Agent框架的最新资料",
    backstory="资深技术分析师",
    tools=[search_tool],
)
writer = Agent(role="撰写者", goal="把资料写成一篇科普文章", backstory="技术作家")

task1 = Task(description="调研主流Agent框架", agent=researcher)
task2 = Task(description="基于调研结果写文章", agent=writer, context=[task1])

crew = Crew(agents=[researcher, writer], tasks=[task1, task2])
crew.kickoff()
```

特点：上手快、概念贴近「岗位」，适合角色清晰的协作场景。

### 2. AutoGen：对话驱动 + 代码执行

微软 AutoGen 核心是「**可对话的 Agent**」，多个 Agent 通过消息对话协作，并内置 `UserProxyAgent` 能执行代码。

```python
from autogen import AssistantAgent, UserProxyAgent

assistant = AssistantAgent("assistant", llm_config={"model": "gpt-4o"})
user_proxy = UserProxyAgent("user_proxy", code_execution_config={"work_dir": "coding"})
user_proxy.initiate_chat(assistant, message="用Python算1到100的和，并画柱状图")
```

特点：对话即编排，配合代码执行器适合「让 Agent 写代码跑代码」的自动化。注意代码执行必须沙箱隔离。

### 3. LangGraph 自定义多 Agent 状态网

用一张大图把多个子 Agent（各为一个 subgraph / 节点）串起来，利用 State + 条件边实现 Manager 调度。

```python
# 伪代码：Manager 节点根据子任务派发到不同 worker 子图
builder.add_node("manager", plan_and_dispatch)
builder.add_node("researcher", researcher_subgraph)
builder.add_conditional_edges("manager", route_to_worker)
```

特点：最灵活、可控、可持久化，适合生产级复杂系统，但开发量最大。

### 选型建议

| 框架 | 一句话 | 适合 |
| -- | -- | -- |
| CrewAI | 像组团队，角色驱动 | 快速搭角色协作 Demo |
| AutoGen | 对话驱动 + 跑代码 | 代码生成/自动化研究 |
| LangGraph | 状态图编排多 Agent | 生产级、可控可观测 |

### 经验

- 先想清楚「协作模式」（见 6.1），再选框架，别被框架带着走；
- 多 Agent 通信轮次直接决定成本，设计时要控制「对话收敛」。
