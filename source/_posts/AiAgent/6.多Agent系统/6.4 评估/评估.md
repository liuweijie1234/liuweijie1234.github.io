## 6.4 多 Agent 系统评估

多 Agent 比单 Agent 更难评估——不仅要看结果对不对，还要看「协作过程效率高不高」。

### 1. 协作效率与通信轮次

- **通信轮次（Communication Rounds）**：完成任务花了多少轮对话。轮次越多，延迟和成本越高。目标是在「充分讨论」和「过度闲聊」间找平衡。
- **任务完成步数 / Token 总量**：多 Agent 天然比单 Agent 费 token，要量化「多花的成本是否换来质量提升」。
- **并行度利用率**：Worker 是否真在并行，还是串行等待（Manager 调度瓶颈）。

### 2. 结果质量对比

- **端到端任务成功率**：最终交付物是否达成目标（同单 Agent 评测标准，见 8.评测）。
- **对比基线**：多 Agent 方案 vs 单 Agent / 纯人工作业，在相同任务上的质量差异。
- **一致性**：多次运行结果是否稳定（多 Agent 随机性更强，方差可能更大）。

### 3. 评估方法

- **人工评审**：对复杂交付物（文章、方案）做专家打分，最可靠但慢。
- **自动化指标**：对可量化的任务（如代码跑通率、检索准确率）写自动校验。
- **A/B 对照**：同一批任务，多 Agent vs 单 Agent，统计成功率、成本、耗时。
- **轨迹分析（Trajectory）**：回放 Agent 间的对话轨迹，看是否有「无效轮次」「冲突未解决」「死循环」，据此优化协作拓扑。

### 4. 常见评估陷阱

- 只看最终结果，忽略通信成本 → 可能「多 Agent 略好一点，但贵十倍」；
- 只跑一次就下结论 → 多 Agent 方差大，要多次取平均；
- 角色设计不合理导致互相拆台 → 评估要暴露「协作失当」而非单纯模型弱。

### 经验口诀

多 Agent 评估 = 「结果质量 × 协作效率」双指标。质量没明显提升时，别为了「看起来高级」硬上多 Agent——单 Agent + 好提示词往往更省更稳。
