## 7.1 服务封装

把 Agent 从「笔记本里的脚本」变成「可被前端/其他服务调用的 API」，是工程化第一步。

### 1. 用 FastAPI 封装 Agent 接口

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ChatReq(BaseModel):
    session_id: str
    message: str

@app.post("/agent/chat")
async def chat(req: ChatReq):
    answer = await run_agent(req.session_id, req.message)  # 你的 Agent 逻辑
    return {"answer": answer}
```

要点：用 Pydantic 模型收请求，做好入参校验；Agent 逻辑放异步函数里，避免阻塞事件循环。

### 2. 流式响应（SSE / WebSocket）

用户不可能等 Agent 想完 10 秒才看到字。要边生成边吐：

- **SSE（Server-Sent Events）**：服务端单向推流，最适合「模型逐字输出」。前端 `EventSource` 接收。

```python
from fastapi.responses import StreamingResponse
import asyncio

@app.post("/agent/chat/stream")
async def chat_stream(req: ChatReq):
    async def event_gen():
        async for token in run_agent_stream(req.message):
            yield f"data: {token}\n\n"   # SSE 格式
    return StreamingResponse(event_gen(), media_type="text/event-stream")
```

- **WebSocket**：双向通信，适合需要「前端中途发指令/干预」的场景（如用户中途改需求）。

选 SSE 还是 WebSocket？纯展示输出用 SSE 足够；需要双向交互（如人在循环中干预）用 WebSocket。

### 3. 异步任务与后台作业

有些任务很慢（生成报告、跑数据分析），不能卡在 HTTP 请求里：

- **Celery / RQ / 消息队列**：把任务丢进队列，前端轮询或回调拿结果；
- **后台任务（BackgroundTasks）**：FastAPI 的 `BackgroundTasks` 处理轻量后置逻辑（如记日志、发通知）；
- 长任务务必返回 `task_id`，前端用「轮询 / WebSocket 推送」跟踪进度。

### 经验

- 接口设计要「无状态 + 靠 session_id 取上下文」，方便水平扩展；
- 流式是基础体验，SSE 最简单先上；
- 同步阻塞代码（如老版 openai 同步调用）会拖垮整个服务，统一用异步客户端。
