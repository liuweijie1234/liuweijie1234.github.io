## 7.2 容器化与云部署

### 1. Docker 镜像构建

把 Agent 服务打包成镜像，环境一致、随处运行。

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

注意：

- 用 `.dockerignore` 排除 `.env`、缓存、大文件；
- 依赖固定版本（`requirements.txt` 锁版本），避免「本地能跑线上崩」；
- 镜像别太大，用 slim 基础镜像 + 多阶段构建。

### 2. 环境变量与密钥管理

- **绝不把 API Key 写进代码或镜像**！统一走环境变量。
- 本地用 `.env`（不提交 git）；生产用云厂商的 Secret 管理（如 K8s Secret、Vault、云密钥服务）。
- Docker 启动时注入：`docker run -e OPENAI_API_KEY=xxx -e REDIS_URL=xxx ...`。

```python
import os
OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")   # 从环境读，不硬编码
```

### 3. Docker Compose 编排

Agent 常依赖多个中间件（Redis 缓存、Postgres 存对话、向量库），用 Compose 一把拉起：

```yaml
version: "3"
services:
  agent:
    build: .
    ports: ["8000:8000"]
    environment:
      - REDIS_URL=redis://redis:6379
    depends_on: [redis]
  redis:
    image: redis:7
```

### 4. Serverless 函数部署（可选）

对流量波动大、按需触发的场景（如定时跑批、事件触发），可用 Serverless（云函数 / 容器实例），按调用计费、自动扩缩。但注意：

- 冷启动延迟（首请求慢）；
- 有状态/长连接（如 WebSocket 长连）不适合纯函数，需用长驻服务。

### 5. 私有化部署

数据敏感场景（金融、政企）要求「模型和数据不出域」：用 vLLM / Ollama 在本地跑开源模型，Agent 框架对接本地推理服务，全程内网闭环（详见「数据隐私」）。

### 经验

- 部署三件套：镜像可复现 + 密钥走环境 + 依赖锁版本；
- 先 Compose 单机跑通，再上 K8s 做高可用（流量大了再说）。
