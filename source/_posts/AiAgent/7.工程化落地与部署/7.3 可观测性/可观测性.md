## 7.3 可观测性（Observability）

Agent 是「概率性系统」，不观测就等于零保障。要盯住三件事：调用链、成本、质量。

### 1. 全链路追踪（LangSmith / LangFuse）

把每次 Agent 运行拆解成可回放的轨迹：每一步调了哪个模型、传了什么工具、花了多 token、耗时多少。

- **LangSmith**：LangChain/LangGraph 官方平台，自动记录节点级轨迹，支持评测数据集。
- **LangFuse**：开源可自托管，支持 trace / 评分 / 数据集，数据敏感时可私有部署。

```python
# LangFuse 装饰器记录一次调用
from langfuse.decorators import observe
@observe()
def run_agent(question):
    return llm_chain(question)
```

价值：出 bug 时一眼看到「是哪一步、哪个 prompt、哪个工具出问题」，而不是盲猜。

### 2. 自定义日志与指标采集

至少采集这些核心指标：

| 指标 | 含义 | 用途 |
| -- | -- | -- |
| token 消耗 | 每次请求 input/output token | 成本统计、异常飙升预警 |
| 延迟（Latency） | 端到端耗时 / 单步耗时 | 性能瓶颈定位 |
| 步数（Steps） | Agent 循环了几轮 | 死循环预警 |
| 工具调用成功率 | 工具成功/失败比 | 外部依赖健康度 |
| 解析失败率 | JSON/结构化解析失败比 | 提示词质量监控 |

用 Prometheus + Grafana 或云平台指标服务采集，自己做 dashboard。

### 3. 告警与大盘可视化

- 大盘：把上面的指标做成实时面板，运营/研发一眼掌握系统健康；
- 告警：token 成本日环比暴涨、解析失败率超阈值、平均步数异常 → 自动通知（钉钉/飞书/邮件）；
- 慢调用、报错调用要能下钻到具体 trace 定位。

### 经验口诀

- 没埋点 = 盲飞。上线前先接追踪 + 指标，再谈优化；
- 优先监控「成本」和「步数」——这俩异常往往最先暴露提示词/模型问题；
- 敏感数据走私有化可观测（LangFuse 自部署），别把用户对话泄露给第三方平台。
