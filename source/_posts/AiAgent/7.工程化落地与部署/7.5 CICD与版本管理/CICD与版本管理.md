## 7.5 CI/CD 与版本管理

Agent 系统里有两类「代码」要管：**传统代码**和**提示词/配置**，两者都要版本化、可回滚。

### 1. 提示词版本管理

提示词不是一次写定，而是持续迭代的资产：

- 把系统提示词、工具描述、few-shot 示例**存成文件 / 配置**，进 Git，而非硬编码在代码里；
- 每次改提示词都留 commit，能对比「哪次改动让成功率掉了」；
- 进阶：用「提示词注册表」，给每个版本打标签，运行时按版本号加载，出问题秒级回滚。

```
prompts/
  system_v3.md
  tools_def.json
  fewshot_refund.json
```

### 2. 模型与 Agent 服务灰度发布

- **模型灰度**：新模型/新提示词先放 5% 流量，对比成功率、成本，没问题再全量；
- **A/B 实验**：新旧两版并行跑，用评测集（见 8.评测）量化差异，数据驱动决策；
- **回滚预案**：任何发布都要能一键回退到上一稳定版。

### 3. CI/CD 流水线

```
代码/提示词 提交 → CI 跑测试(单测+评测集) → 构建镜像 → 推仓库 → CD 灰度部署 → 监控验证 → 全量
```

- CI 里除了单测，建议跑**提示词回归测试**：用固定 bad-case 集验证改动没引入退化；
- CD 用 GitHub Actions / GitLab CI / ArgoCD 自动化部署（参考运维知识树的 CI/CD 模块）。

### 经验

- 提示词和代码同等重要，必须版本化、可回滚；
- 没有「评测集守卫」的提示词改动，就是裸奔——改完跑一遍回归再上线；
- 灰度发布能把「线上翻车」的影响控制在最小范围。
