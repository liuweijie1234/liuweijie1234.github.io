## 7.6 Agent 成本控制与限流

Agent 的 token 消耗是「乘法级」的——每轮循环都要重发一遍上下文，几轮下来账单吓人。必须主动管控。

### 1. 为什么成本容易失控

- **上下文复利**：每步都把「历史 + 工具结果 + 指令」重新发给模型，步数越多，单轮 token 越膨胀；
- **模型选配不当**：简单分类用旗舰模型，纯属浪费；
- **无终止兜底**：死循环疯狂调模型，成本爆炸。

### 2. 成本优化手段

- **分层用模型**：路由/分类/摘要用便宜小模型（如 gpt-4o-mini / 本地模型），只有复杂推理才上大模型；
- **上下文压缩**：历史对话摘要化、检索结果只留相关句、超长截断（见「记忆系统」「生成增强」）；
- **前缀缓存**：不变的系统指令 + 工具定义放最前，命中缓存省重复计算（见「框架机制剖析」）；
- **控制步数**：`max_steps` 上限 + 早停，避免无谓循环；
- **结果缓存**：相同/相似 query 直接返回历史结果，高频问题零成本。

### 3. 限流（Rate Limiting）

保护服务和钱包：

- **用户级限流**：每用户每分钟 N 次，防单用户刷爆；
- **全局限流**：保护下游模型 API 不超过配额，避免 429 限流错误；
- **并发控制**：限制同时运行的 Agent 数，防止资源打满。

```python
from slowapi import Limiter
limiter = Limiter(key_func=get_user_id)

@app.post("/agent/chat")
@limiter.limit("10/minute")        # 每用户每分钟 10 次
async def chat(req: ChatReq):
    ...
```

### 4. 成本可观测

- 按用户/按会话统计 token 消耗，异常账户及时告警；
- dashboard 展示「日均成本 / 单请求成本分布」，定位贵请求。

### 经验口诀

成本 = 模型单价 × token 量 × 步数。三处都能砍：选便宜模型、压上下文、限步数。上线前先算清「单次对话成本上限」。
