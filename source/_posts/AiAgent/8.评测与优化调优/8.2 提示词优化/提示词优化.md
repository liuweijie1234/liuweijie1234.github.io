## 8.2 提示词优化

提示词是 Agent 性价比最高的调优杠杆——不用改架构，改几句话可能成功率涨一大截。

### 1. 自动化调优（DSPy 思路）

传统手写提示词靠试错，DSPy 类思路用**数据驱动**自动搜出最优提示词（见「提示词工程 / 自动调优 DSPy」）。即便不引入框架，也可借鉴：

- 准备标注样本集（输入 + 期望输出）；
- 写脚本批量跑不同提示词变体；
- 用评测指标自动挑最优。

### 2. A/B 测试与对比实验

```python
# 伪代码：批量对比两个提示词版本
for case in test_set:
    a = run_with_prompt(prompt_v1, case)
    b = run_with_prompt(prompt_v2, case)
    score_a, score_b = evaluate(a), evaluate(b)
# 统计 win/tie/lose，v2 显著胜出才上线
```

原则：

- 一次只改一个变量（指令措辞 / few-shot 示例 / 格式），否则不知是谁起作用；
- 用足够样本量，避免「刚好这条赢了」的偶然；
- 上线走灰度（见「CI/CD 与版本管理」）。

### 3. 错误案例分析（Error Analysis）

把 bad case 按根因归类，针对性改提示词：

| 根因 | 提示词改造 |
| -- | -- |
| 选错工具 | 工具描述补触发场景 + 加 few-shot |
| 参数错 | 参数 description 加示例 / enum 约束 |
| 答非所问 | 加「只依据资料」硬约束 |
| 死循环 | 加「拿到观察先判断是否够答」 |
| 输出格式错 | 用 Structured Output 强约束 |

### 4. 迭代闭环

```
线上 bad case → 归类根因 → 改提示词 → 回归测试集 → 灰度 → 全量 → 监控
```

### 经验口诀

提示词优化 = 数据（测试集） + 变量控制（单点改） + 回归（防退化）。没有测试集守卫的「灵光一现式修改」，上线必翻车。
