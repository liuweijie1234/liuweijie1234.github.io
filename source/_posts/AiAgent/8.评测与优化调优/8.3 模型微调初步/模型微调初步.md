## 8.3 模型微调初步

当「提示词 + RAG + 工具」都到顶了，仍不满足，才考虑微调。微调不是万能药，先想清楚要不要。

### 1. 何时需要微调

优先用更便宜的手段解决：

- 知识过时 → 用 **RAG**（别微调，知识易变）；
- 输出格式不稳 → 用 **Structured Output / 提示词约束**；
- 特定风格/口吻 → 提示词 few-shot 往往够。

考虑微调的信号：

- 任务高度固定、重复（如特定格式的工单分类）；
- 需要模型「学会某种推理模式」而非「记住知识」；
- 对延迟/成本极敏感，想用小模型替代大模型（蒸馏思路）；
- 私有化场景，必须用本地小模型且效果要达标。

### 2. 数据构造方法（指令数据集）

微调的本质是「喂高质量 (指令, 输出) 对」：

- **人工编写**：专家手写输入输出，质量最高但慢；
- **蒸馏**：用强模型（GPT-4）对弱模型要学的任务生成样本；
- **现有数据转化**：从历史对话/业务记录里清洗出 (输入, 期望输出)；
- 数据要**去重、去噪、平衡类别**，脏数据比少数据更伤模型。

```
{"instruction": "判断用户意图", "input": "我要退昨天买的鞋", "output": "退款"}
```

### 3. LoRA / QLoRA 高效微调概念

全量微调（Full Fine-tuning）成本高、易遗忘。主流用**参数高效微调（PEFT）**：

- **LoRA（Low-Rank Adaptation）**：冻结原模型，只训练额外插入的「低秩矩阵」，参数量可能只有原模型的 0.1%~1%，显存友好、可插拔（一个底座挂多个 LoRA 适配不同任务）。
- **QLoRA**：在 LoRA 基础上用 4-bit 量化加载底座，消费级显卡（如单张 24G）也能微调 7B~13B 模型。

```python
# 伪代码（peft + transformers 思路）
from peft import LoraConfig, get_peft_model
config = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj","v_proj"])
model = get_peft_model(base_model, config)
train(model, dataset)   # 只训 LoRA 部分
```

### 4. 微调后的工程注意

- 微调后仍需提示词 + 评测集回归；
- 小模型微调后可能「只会这一件事」，通用能力变弱，路由时要区分；
- 模型版本要管理，能回滚。

### 经验口诀

**能 RAG 不微调，能提示词不微调**。微调是「最后一招」，用来解决提示词和 RAG 搞不定的「能力缺口」，且务必配高质量数据集 + 严格评测。
