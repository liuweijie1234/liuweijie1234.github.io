## 9.2 权限与审计

Agent 一旦能「执行操作」，就必须有类似「员工权限体系」的控制与留痕。

### 1. 工具调用权限分级

不是所有工具都该对 Agent 一视同仁：

| 等级 | 工具示例 | 控制 |
| -- | -- | -- |
| 只读低危 | 查天气、查公开资料 | 自动执行 |
| 写操作中危 | 创建工单、发站内信 | 限频 + 记录 |
| 高危 | 退款、发邮件、删数据 | 必须人工确认 |

实现：给每个工具打 `risk_level` 标签，执行前按级别走不同流程。

### 2. 关键操作人类确认（Human-in-the-loop）

高权限动作不能让模型「自作主张」：

```python
def execute_tool(call):
    tool = get_tool(call.name)
    if tool.risk == "high":
        evt = emit_confirm_request(call)   # 前端弹确认框
        if not wait_user_approval(evt):
            return "用户拒绝了该操作"        # 回灌给模型换方案
    return tool.run(call.args)
```

价值：把「最终决策权」留在人手里，避免模型误伤（误退款、误删库）。

### 3. 完整审计日志

每一次 Agent 运行都要可回溯：

- 记录：用户是谁、输入什么、调了哪些工具及参数、模型如何决策、最终输出、耗时、token；
- 存到不可篡改的日志系统，支持按会话/trace 检索；
- 既是合规要求，也是 debug 和追责的依据。

### 4. 角色权限管控（RBAC）

- 不同用户/部门对 Agent 的能力不同（如客服只能查订单，不能退款）；
- 结合「数据权限隔离」（见 9.3），做到「人-权-数」三对应。

### 经验

- 权限设计遵循**最小权限原则**：默认什么都干不了，按需开放；
- 高危操作「人工确认 + 审计日志」是生产底线，缺一不可；
- 没有审计的 Agent，出事后无法定责，企业绝不敢用。
