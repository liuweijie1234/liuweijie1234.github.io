## 9.3 数据隐私

企业级 Agent 最常卡在「数据不能出公司」。隐私设计要贯穿全链路。

### 1. 用户数据隔离

多租户场景下，A 用户绝不能看到 B 用户的数据：

- **检索层隔离**：RAG 查询强制带 `owner_id` / `dept` 元数据过滤（见「混合检索与元数据过滤」）；
- **记忆隔离**：长期记忆按用户维度存储，查询时严格按当前用户身份取；
- **上下文隔离**：同一会话的产物不串到其他会话。

```python
hits = vector_db.query(
    q, where={"dept": current_user.dept, "owner": current_user.id}
)
```

### 2. 本地模型数据不出域

对金融、政企等强合规场景：

- 用 **vLLM / Ollama / LM Studio** 在本地/内网部署开源模型（Qwen、Llama、DeepSeek 等）；
- Agent 框架对接本地推理端点（如 `http://internal-llm:8000/v1`），不连任何公网 API；
- 向量库、数据库、日志全部内网部署，形成**完全闭环**；
- 即使如此，内部也要做权限分级与审计（内网≠无管控）。

### 3. PII 处理与脱敏

- 入库前对敏感字段（身份证、手机号）脱敏或加密；
- 输出前再次扫描 PII 并打码（见 9.1）；
- 日志里不落明文敏感信息。

### 4. 合规要点速记

- **可审计**：谁在何时查了什么，全程留痕；
- **可追溯**：答案能标注来源，便于核查；
- **可删除**：用户要求删除数据，要有「遗忘」机制（删记忆、删向量）；
- **最小化**：只收集/使用必要数据。

### 经验

- 数据隐私不是「技术加分项」，而是「能不能用」的准入门槛；
- 出海业务还要看 GDPR 等法规，「被遗忘权」「数据本地化」是硬要求；
- 最稳方案：敏感业务一律本地模型 + 内网闭环 + 权限审计三件套。
