## 一、请求头的作用

请求头（Request Headers）携带**请求的元信息**：身份、内容类型、缓存、客户端环境等，帮助服务器正确处理。

## 二、常用请求头

| Header | 作用 |
|--------|------|
| `Host` | 目标主机（虚拟主机路由必需） |
| `User-Agent` | 客户端浏览器/系统 |
| `Accept` | 可接受的响应类型 |
| `Content-Type` | 请求体格式（如 `application/json`） |
| `Authorization` | 认证凭证（`Bearer <token>`） |
| `Cookie` | 客户端 Cookie |
| `Referer` | 来源页 |
| `Origin` | 跨域请求来源（CORS 用） |
| `Cache-Control` | 缓存策略 |
| `If-None-Match` / `If-Modified-Since` | 条件请求（304） |

## 三、Content-Type 对照

- `application/json`：JSON 体（API 主流）。
- `application/x-www-form-urlencoded`：表单默认。
- `multipart/form-data`：文件上传。
- `text/plain`：纯文本。

## 四、响应头补充

| Header | 作用 |
|--------|------|
| `Set-Cookie` | 下发 Cookie |
| `Location` | 3xx 跳转地址 |
| `Cache-Control` / `ETag` | 缓存控制 |
| `Content-Type` / `Content-Length` | 响应体描述 |
| `Access-Control-Allow-Origin` | CORS 允许来源 |
| `WWW-Authenticate` | 认证挑战 |

## 五、调试方法

- 浏览器 DevTools → Network 看请求/响应头。
- `curl -i` / `curl -H` 模拟带头请求。
- 抓包：Charles / Fiddler。

## 六、最佳实践

- 只在 `Authorization` 放凭证，别塞进 URL（会被日志泄露）。
- 上传用 `multipart/form-data`；API 用 `application/json`。
- 利用 `ETag`/`Cache-Control` 做缓存优化（见 `cookie与session.md`）。
