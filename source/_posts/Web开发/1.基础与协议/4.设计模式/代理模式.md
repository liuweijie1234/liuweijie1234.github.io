## 一、意图

**代理模式**为另一个对象提供**替身/占位**，以控制对原对象的访问（延迟加载、权限、缓存、远程调用）。

## 二、结构

```
Subject (接口) ← RealSubject(真实) / Proxy(代理)
Proxy 持有 RealSubject 引用，调用前后可加控制逻辑。
```

## 三、常见变体

- **虚拟代理**：延迟创建昂贵对象（如大图懒加载）。
- **保护代理**：访问控制（权限校验）。
- **远程代理**：本地代表远程对象（RPC/HTTP 客户端）。
- **缓存代理**：缓存结果（如 ORM 查询缓存）。

## 四、Python 示例

```python
class Image:
    def display(self): print('load & show image')

class ProxyImage:
    def __init__(self): self._img = None
    def display(self):
        if self._img is None:
            self._img = Image()        # 延迟加载
        self._img.display()

p = ProxyImage()
p.display()   # 第一次才真正创建
```

## 五、Web 中的体现

- ORM 的懒加载（`lazy=True` 关联）即虚拟代理。
- 反向代理（Nginx）是远程代理，隐藏真实后端。
- API 网关对后端的代理访问，附加鉴权/限流。
- Django 的 `QuerySet` 延迟执行（lazy），用到时才发 SQL。

## 六、最佳实践

- 代理与真实对象实现同一接口，调用方无感。
- 用代理把横切逻辑（缓存、权限、日志）与业务分离。
- 别为简单对象硬套代理，徒增复杂度。
