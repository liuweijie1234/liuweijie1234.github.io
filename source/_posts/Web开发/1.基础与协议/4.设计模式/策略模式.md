## 一、意图

**策略模式**定义一系列**可互换的算法**，把它们封装起来，使它们可独立于使用它的客户而变化。

## 二、结构

```
Context(上下文) 持有 Strategy(策略接口)
具体策略 A / B / C 实现同一接口
运行时注入不同策略，行为随之改变
```

## 三、Python 示例

```python
from abc import ABC, abstractmethod

class Discount(ABC):
    @abstractmethod
    def calc(self, price): ...

class NoDiscount(Discount):
    def calc(self, p): return p

class PercentOff(Discount):
    def __init__(self, rate): self.rate = rate
    def calc(self, p): return p * (1 - self.rate)

def checkout(price, strategy: Discount):
    return strategy.calc(price)

checkout(100, PercentOff(0.2))   # 80
```

Python 里策略也可以是函数（一等公民），更轻量：

```python
strategies = {'flat': lambda p: p, 'half': lambda p: p/2}
strategies['half'](100)
```

## 四、Web 中的应用

- 支付方式切换（支付宝/微信/银行卡）。
- 序列化策略（JSON/XML/Protobuf）。
- 限流算法（令牌桶/漏桶）可插拔（见 `4.基础设施与扩展/2.高并发`）。
- 缓存后端切换（Redis/LocMem）。

## 五、与工厂/依赖注入结合

用工厂按配置选出策略，或经依赖注入注入策略实例，降低耦合。

## 六、最佳实践

- 当 `if/elif` 分支只是「选不同算法」时，考虑策略模式。
- Python 用函数/lambda 当策略足够，不必硬写类层级。
- 策略应无状态且可复用；有状态需小心并发。
