## 一、意图

**装饰器模式**动态地给对象/函数**附加职责**，而不改变其原有结构。Python 的 `@decorator` 语法糖是其最直观体现。

## 二、函数装饰器

```python
import time, functools

def timing(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        t = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f'{func.__name__} cost {time.perf_counter()-t:.3f}s')
    return wrapper

@timing
def work(): ...
```

`@functools.wraps` 保留原函数元信息（名称、文档）。

## 三、带参装饰器

```python
def retry(times=3):
    def deco(func):
        @functools.wraps(func)
        def wrapper(*a, **k):
            for i in range(times):
                try:
                    return func(*a, **k)
                except Exception:
                    if i == times-1: raise
        return wrapper
    return deco
```

## 四、类装饰器

装饰器也可以是类（实现 `__call__`），或装饰类（`@dataclass`、`@login_required` 装饰 `View`）。

## 五、Web 框架中的应用

- Django 的 `@login_required`、`@permission_required`。
- Flask 的 `@app.route`（本质是注册路由的装饰器）。
- 统一日志、鉴权、缓存、重试等横切关注点。

## 六、最佳实践

- 用 `functools.wraps` 保留元信息，避免调试/文档错乱。
- 装饰器保持单一职责、可组合。
- 过多嵌套装饰器影响可读性，复杂逻辑考虑中间件/依赖注入（FastAPI `Depends`、Django middleware）。
