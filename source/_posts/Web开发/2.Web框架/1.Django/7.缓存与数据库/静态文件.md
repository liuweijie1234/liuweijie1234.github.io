## 一、静态文件分类

- **static（静态文件）**：CSS、JS、图片等随代码发布的资源。
- **media（用户上传）**：运行时用户上传的文件（见 `3.模板与表单/表单Forms.md` 的文件上传）。

本文聚焦 static。

## 二、配置

```python
STATIC_URL = '/static/'
STATICFILES_DIRS = [BASE_DIR / 'static']     # 项目级静态目录
STATIC_ROOT = BASE_DIR / 'staticfiles'       # collectstatic 收集目标
```

各 app 也可自带 `app/static/app/...`，`APP_DIRS` 自动发现。

## 三、模板中引用

```html
{% load static %}
<link rel="stylesheet" href="{% static 'blog/style.css' %}">
<img src="{% static 'blog/logo.png' %}">
```

`{% static %}` 会输出带 `STATIC_URL` 前缀的路径。

## 四、收集与部署

开发环境 `django.contrib.staticfiles` 自动服务；生产环境用 `collectstatic` 把分散的静态文件汇总到 `STATIC_ROOT`，再由 Nginx 等直接托管：

```bash
python manage.py collectstatic --noinput
```

Nginx：

```nginx
location /static/ {
    alias /path/to/staticfiles/;
    expires 30d;
    access_log off;
}
```

## 五、最佳实践

- 生产环境**不要**让 Django 自己服务静态文件，交给 Web 服务器，性能更好。
- 用 `ManifestStaticFilesStorage` 启用文件指纹（内容哈希），彻底解决浏览器缓存更新问题：

```python
STATICFILES_STORAGE = 'django.contrib.staticfiles.storage.ManifestStaticFilesStorage'
```

- 静态资源按 app 分目录，避免命名冲突；配合前端构建工具（webpack/Vite）时，`STATICFILES_DIRS` 指向打包产物目录。
