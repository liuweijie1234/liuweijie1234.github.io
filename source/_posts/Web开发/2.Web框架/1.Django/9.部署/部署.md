## 一、部署架构

```
浏览器 → Nginx（反向代理 + 静态文件 + HTTPS）
            → Gunicorn（WSGI 服务器，跑 Django）
                → Django app → PostgreSQL/Redis
```

`uwsgi.md` 介绍了 uWSGI 方案；本文以 **Gunicorn + Nginx** 为主流推荐。

## 二、生产配置 checklist

`settings.py`：

```python
DEBUG = False
ALLOWED_HOSTS = ['example.com', 'www.example.com']
# 安全
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
```

收集静态文件：`python manage.py collectstatic`。

## 三、Gunicorn 启动

```bash
pip install gunicorn
gunicorn config.wsgi:application -w 4 -k gthread -b 127.0.0.1:8000 --timeout 60
```

- `-w`：worker 数，通常 `2 * CPU + 1`。
- `-k gthread`：线程模式，适合 I/O 密集型；也可用 `uvicorn.workers.UvicornWorker` 跑 ASGI。
- 用 `systemd` 托管 Gunicorn，保证崩溃自启。

`/etc/systemd/system/gunicorn.service` 示例：

```ini
[Unit]
Description=gunicorn django
After=network.target

[Service]
User=www
WorkingDirectory=/srv/project
ExecStart=/srv/venv/bin/gunicorn config.wsgi:application -w 4 -b 127.0.0.1:8000
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 四、Nginx 反向代理

```nginx
server {
    listen 80;
    server_name example.com;
    location /static/ { alias /srv/project/staticfiles/; }
    location /media/  { alias /srv/project/media/; }
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 五、HTTPS（Certbot）

```bash
certbot --nginx -d example.com
```

Certbot 自动改写 Nginx 配置并续期。

## 六、进程管理与监控

- 用 `systemd` / `supervisor` 托管 Gunicorn。
- 日志：集中到文件 + 采集（如 ELK / Grafana Loki）。
- 健康检查：`/healthz` 视图返回 200。
- 数据库迁移：`manage.py migrate` 在发布流程中执行；配合 `gunicorn --preload` 时注意多进程下只跑一次。

## 七、最佳实践

- 永远 `DEBUG=False` 上线；`SECRET_KEY` 用环境变量注入，不入库。
- 静态/媒体由 Nginx 直出，Gunicorn 只跑动态请求。
- 用虚拟环境隔离依赖，固定 `requirements.txt` 版本。
- 灰度发布 + 数据库迁移向后兼容（先加字段后删旧字段）。
