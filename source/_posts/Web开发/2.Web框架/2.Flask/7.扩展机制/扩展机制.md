## 一、Flask 扩展生态

Flask 的「微」体现在核心精简，功能靠**扩展**补齐。官方维护的 `Flask-*` 系列覆盖绝大多数需求。

## 二、常用扩展

| 扩展 | 用途 |
|------|------|
| Flask-SQLAlchemy | ORM |
| Flask-Migrate | 数据库迁移 |
| Flask-WTF | 表单与 CSRF |
| Flask-Login | 用户认证会话 |
| Flask-Mail | 发邮件 |
| Flask-RESTful / Flask-RESTX | 构建 REST API |
| Flask-Caching | 缓存 |
| Flask-JWT-Extended | JWT 认证 |
| Flask-CORS | 跨域 |
| Flask-SocketIO | WebSocket |

## 三、扩展的初始化模式

多数扩展通过「先实例化、再 `init_app(app)`」与 app 解耦，配合应用工厂：

```python
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate

db = SQLAlchemy()
migrate = Migrate()

def create_app():
    app = Flask(__name__)
    db.init_app(app)
    migrate.init_app(app, db)
    return app
```

## 四、Flask-Login 示例

```python
from flask_login import LoginManager, login_user, login_required, current_user

login_manager = LoginManager()
login_manager.init_app(app)

@login_manager.user_loader
def load_user(uid):
    return User.query.get(int(uid))

@app.route('/dashboard')
@login_required
def dashboard():
    return f'hello {current_user.username}'
```

## 五、自己写扩展

扩展本质是一个封装了 `init_app` 的类，或提供蓝图/装饰器的模块。保持与官方一致的 `init_app` 约定即可被应用工厂复用。

## 六、最佳实践

- 优先用社区成熟扩展，少造轮子。
- 所有扩展都在 `create_app` 里 `init_app`，避免全局单例污染测试。
- 关注扩展对 Flask 版本的兼容性（Flask 2.x/3.x）。
