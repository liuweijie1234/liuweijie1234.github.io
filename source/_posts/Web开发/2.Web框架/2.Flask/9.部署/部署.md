## 一、为什么不用 app.run() 上线

`app.run()` 内置的 Werkzeug 服务器**仅供开发**，单线程、无安全加固。生产用 **Gunicorn/uWSGI + Nginx**。

## 二、Gunicorn 启动

```bash
pip install gunicorn
gunicorn -w 4 -b 127.0.0.1:8000 "app:create_app()"
```

- `-w`：worker 数（`2*CPU+1`）。
- 若用工厂函数，写成 `"app:create_app()"`。
- 用 `gevent` worker 处理长连接/WebSocket（需 `gunicorn[gevent]`）。

`systemd` 托管示例同 Django 部署；核心是 `ExecStart` 指向 gunicorn 命令。

## 三、Nginx 反向代理

```nginx
server {
    listen 80;
    server_name example.com;
    location /static/ { alias /srv/project/static/; }
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 四、配置与密钥管理

```python
import os
app.config['SECRET_KEY'] = os.environ['SECRET_KEY']
app.config['SQLALCHEMY_DATABASE_URI'] = os.environ['DATABASE_URL']
```

`DEBUG=False`，敏感配置全部走环境变量（可用 `python-dotenv` 加载 `.env`，但 `.env` 勿入库）。

## 五、容器化部署

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:8000", "app:app"]
```

## 六、最佳实践

- 静态文件走 Nginx；Flask 只处理动态请求。
- 用进程管理器（systemd/supervisor/K8s）保证存活与滚动发布。
- 加健康检查路由 `/healthz`。
- 日志结构化输出到 stdout，由平台采集。
