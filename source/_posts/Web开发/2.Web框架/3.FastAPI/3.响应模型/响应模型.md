## 一、用 response_model 约束出参

```python
from pydantic import BaseModel

class ItemOut(BaseModel):
    id: int
    name: str

@app.post('/items/', response_model=ItemOut)
def create_item(item: ItemIn):
    return Item(id=1, name=item.name, secret='不返回')
```

`response_model` 会自动**过滤掉未在模型中声明的字段**（如 `secret`），既防泄露又统一文档。

## 二、response_model 的好处

- 自动序列化与校验输出。
- 屏蔽内部/敏感字段。
- `/docs` 中生成准确的响应 schema。

## 三、常用配置

```python
@app.get('/items/', response_model=list[ItemOut], response_model_exclude_unset=True)
def list_items():
    ...
```

- `response_model_exclude_unset=True`：只返回被显式赋值的字段，避免默认空值。
- `response_model_include` / `response_model_exclude`：按需挑选字段。

## 四、状态码与响应

```python
@app.post('/items/', status_code=201, response_model=ItemOut)
def create(): ...
```

`status_code` 声明成功状态码（也进文档）。

## 五、自定义 Response

```python
from fastapi.responses import JSONResponse, HTMLResponse, PlainTextResponse

@app.get('/html', response_class=HTMLResponse)
def html():
    return '<h1>hi</h1>'
```

文件/流式/重定向用 `FileResponse`/`StreamingResponse`/`RedirectResponse`。

## 六、最佳实践

- 入参模型（ItemIn）与出参模型（ItemOut）分离，安全且职责清晰。
- 用 `response_model_exclude_unset` 让 PATCH 类接口返回更贴合实际。
- 错误用 `HTTPException(status_code=4xx, detail=...)`，不要手动拼 JSON。
