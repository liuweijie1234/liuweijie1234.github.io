## 一、async 视图

FastAPI 基于 ASGI，原生支持 `async def`：

```python
@app.get('/')
async def root():
    result = await some_async_io()
    return result
```

- `async def`：适合 I/O（DB、HTTP 调用），单进程可并发处理大量请求。
- `def`：适合 CPU 密集或同步阻塞库，FastAPI 用线程池跑。

## 二、异步数据库驱动

配合同步 ORM（SQLAlchemy）用 `def` + 线程池；或用原生异步驱动：

```python
import databases
database = databases.Database('postgresql+asyncpg://...')

@app.on_event('startup')
async def startup():
    await database.connect()
```

## 三、BackgroundTasks 后台任务

把耗时但不必等结果的操作放到响应后执行：

```python
from fastapi import BackgroundTasks

def send_email(email: str):
    ...

@app.post('/signup')
async def signup(bg: BackgroundTasks, email: str):
    bg.add_task(send_email, email)
    return {'msg': 'ok'}
```

`send_email` 在响应返回后才执行。

## 四、依赖里的后台任务

```python
def write_log(msg: str, bg: BackgroundTasks):
    bg.add_task(persist, msg)

@app.get('/x', dependencies=[Depends(write_log)])
def x(): ...
```

## 五、何时用 Celery/RQ

`BackgroundTasks` 是进程内、随 worker 重启丢失。真正的**可靠异步队列**（重试、分布式、可持久化）用 **Celery**（见 `3.异步任务与消息队列/1.Celery`）。

## 六、最佳实践

- I/O 密集型用 `async` + 异步驱动；CPU 密集用 `def` 或丢给进程池/Celery。
- 轻量后置动作（发邮件、写日志）用 `BackgroundTasks`；重要任务用 Celery 保证不丢。
- 避免 `async` 函数里调用阻塞同步库（会卡住事件循环）。
