## 一、统一响应格式

```json
{ "code": 0, "data": {...}, "message": "ok" }
```

或纯 RESTful（直接返回资源 + HTTP 状态码）。团队内保持一致即可。

## 二、分页、过滤、排序

```http
GET /articles?page=1&size=20&sort=-created_at&author=alice&tag=python
```

返回带分页元信息：

```json
{ "data": [...], "pagination": { "page": 1, "size": 20, "total": 135 } }
```

## 三、安全

- 全站 HTTPS；敏感字段加密存储。
- 认证用 `Authorization: Bearer <token>`（JWT/OAuth2，见 `1.基础与协议/5.认证与权限`）。
- 限流防滥用（见 `4.基础设施与扩展/2.高并发`）。
- 最小权限；对写操作做所有权校验。
- 输入校验不可信（FastAPI Pydantic / Django Forms）。

## 四、性能

- 列表接口加索引；DB 用 `select_related`/`prefetch_related` 防 N+1。
- 热点数据加缓存（见 Django `7.缓存与数据库/缓存Cache.md`）。
- 大响应用分页/流式；字段按需投影（`?fields=id,title`）。

## 五、文档与可观测

- 用 OpenAPI/Swagger（FastAPI 自动生成；Django/Flask 用 `drf-spectacular`/`flasgger`）。
- 记录请求日志、埋点、链路追踪。
- 提供错误码字典。

## 六、前端协作

- 稳定契约：先定 API 契约（OpenAPI）再并行开发。
- 用 `Mock` 服务让前端提前联调。
- 版本兼容策略明确，避免频繁 breaking change。

## 七、检查清单

- [ ] URI 名词复数、无动词
- [ ] 正确使用动词与状态码
- [ ] 统一错误结构
- [ ] 鉴权与限流到位
- [ ] 文档与版本化清晰
- [ ] 分页/过滤/排序可用
