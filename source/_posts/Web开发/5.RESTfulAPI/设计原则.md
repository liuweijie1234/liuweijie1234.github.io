## 一、REST 的核心思想

REST 是一种**以资源为中心**的架构风格，用统一接口（HTTP 动词）操作资源，强调**无状态、可寻址、自描述**。

## 二、资源与 URI

- 资源用**名词复数**表示：`/users`、`/articles`、`/articles/1/comments`。
- URI 标识资源，不暴露动词：`GET /articles/1` 而非 `GET /getArticle?id=1`。
- 层级用嵌套表达从属：`/users/1/articles`。

## 三、用 HTTP 动词表达操作

| 方法 | 语义 | 幂等 |
|------|------|------|
| GET | 查 | 是 |
| POST | 建 | 否 |
| PUT | 整体更新 | 是 |
| PATCH | 部分更新 | 否 |
| DELETE | 删 | 是 |

## 四、无状态

每次请求必须**自带全部上下文**（认证、参数），服务器不保留会话状态。便于水平扩展。

## 五、统一接口与表现层

- 同一资源可有不同表现（JSON/XML），由 `Accept` 协商。
- 用 `Content-Type` 表明请求体格式（`application/json`）。
- 响应包统一的错误结构：`{"error": {"code": "", "message": ""}}`。

## 六、HATEOAS（可选进阶）

响应中提供相关链接，让客户端「可发现」下一步操作：

```json
{
  "id": 1, "title": "x",
  "links": [{"rel": "comments", "href": "/articles/1/comments"}]
}
```

## 七、最佳实践

- URI 用名词、复数、小写、连字符。
- 用正确的 HTTP 动词与状态码（见 `状态码与版本控制.md`）。
- 过滤/排序/分页用查询参数：`?page=2&size=20&sort=-created_at`。
- 保持无状态，认证放 `Authorization` 头。
