# MySQL 事务与并发控制

> 事务是数据库区别于文件系统的根本。本文串起 ACID、隔离级别、锁机制、MVCC 与悲观/乐观锁，让你既能答八股，也能排线上并发问题。

---

## 1. 事务与 ACID

事务是一组不可分割的 SQL 操作，具备四个特性：

| 特性 | 含义 | 实现机制 |
| --- | --- | --- |
| **A**tomicity 原子性 | 全做或全不做 | undo log 回滚 |
| **C**onsistency 一致性 | 数据从一个一致态到另一个 | 应用层 + 约束 |
| **I**solation 隔离性 | 并发事务互不干扰 | 锁 + MVCC |
| **D**urability 持久性 | 提交后不丢 | redo log + 双写 |

```sql
START TRANSACTION;          -- 或 BEGIN
UPDATE account SET bal = bal - 100 WHERE id = 1;
UPDATE account SET bal = bal + 100 WHERE id = 2;
COMMIT;                     -- 提交
ROLLBACK;                   -- 回滚
```

## 2. 隔离级别与并发问题

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交 Read Uncommitted | ❌ 可能 | ❌ 可能 | ❌ 可能 |
| 读已提交 Read Committed | ✅ | ❌ 可能 | ❌ 可能 |
| 可重复读 Repeatable Read（**默认**） | ✅ | ✅ | ✅（快照+间隙锁） |
| 串行化 Serializable | ✅ | ✅ | ✅ |

- **脏读**：读到别的事务**未提交**的数据；
- **不可重复读**：同一事务内两次读**同一行**结果不同（被别的事务更新）；
- **幻读**：同一事务内两次**范围查询**行数不同（被别的事务插入/删除）。

```sql
SELECT @@transaction_isolation;       -- 8.0
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

> InnoDB 在 **RR** 下通过 **MVCC 快照读 + Next-Key Lock 当前读** 解决了幻读（标准 SQL 中 RR 不保证防幻读，这是 MySQL 的增强）。

## 3. 锁机制

### 3.1 锁的粒度

- **表锁**：开销小、冲突高（`LOCK TABLES`、DDL 常用）；
- **行锁**：开销大、并发高，**InnoDB 默认**，基于索引项加锁（无索引则升级为表锁！）。

### 3.2 行锁类型

- **Record Lock**：锁单条记录；
- **Gap Lock**：锁记录间的「间隙」，防插入（解决幻读）；
- **Next-Key Lock**：Record + Gap，左开右闭区间；
- **意向锁（IS/IX）**：表级，标识「事务准备在行上加共享/排他锁」，避免表锁与行锁冲突时逐行检查。

### 3.3 读写锁

- **共享锁 S（读锁）**：`SELECT ... LOCK IN SHARE MODE`，多事务可同时读；
- **排他锁 X（写锁）**：`SELECT ... FOR UPDATE` / `UPDATE` / `DELETE`，互斥。

### 3.4 死锁

两个事务互相等待对方持有的锁。InnoDB 用 **等待图** 检测，回滚代价小的事务。

```ini
innodb_lock_wait_timeout = 50   # 锁等待超时
innodb_deadlock_detect = ON    # 死锁检测（默认开）
```

> 防死锁：固定加锁顺序、缩短事务、降低隔离级别、减小锁范围。

## 4. MVCC 多版本并发控制

MVCC 让「读不加锁、读写不阻塞」，核心是 **undo log 版本链 + ReadView**。

### 4.1 版本链

每行有隐藏列 `DB_TRX_ID`（最近修改事务 ID）与 `DB_ROLL_PTR`（指向 undo 中旧版本）。每次更新，旧版本写入 undo，新行 `ROLL_PTR` 指向它，形成链表。

### 4.2 ReadView（快照）

事务开启时生成 ReadView，记录当前活跃事务 ID 列表。读数据时沿版本链找**对当前事务可见**的版本：

- 若版本的 `trx_id` < 活跃最小 ID → 已提交，可见；
- 若 `trx_id` 在活跃列表中 → 未提交，不可见，继续找旧版本；
- RR 下 ReadView 在**事务首次读时**生成（整个事务复用）；RC 下**每次读**都生成新 ReadView（所以能看到别人已提交的修改 → 不可重复读）。

> 这就是「快照读(Snapshot Read)」：普通 `SELECT` 不加锁。`SELECT ... FOR UPDATE` 是「当前读」，读最新已提交版本并加锁。

---

## 5. 悲观锁 vs 乐观锁

### 5.1 悲观锁（Pessimistic Lock）

假设冲突必然发生，先加锁再操作：

```sql
BEGIN;
SELECT * FROM orders WHERE id = 1 FOR UPDATE;  -- 当前读 + 行锁
-- 业务处理
UPDATE orders SET status = 'paid' WHERE id = 1;
COMMIT;
```

适用于写冲突频繁的场景。

### 5.2 乐观锁（Optimistic Lock）

假设冲突少，不加锁，提交时校验版本：

```sql
-- 表加 version 字段
UPDATE orders SET status='paid', version=version+1
WHERE id=1 AND version=1;   -- 影响行数=0 表示被别人改过，重试
```

或用 `CAS` 业务字段：`WHERE stock>0 AND ...`。适用于读多写少、冲突低场景，并发度高。

---

## 6. 小结

事务的「隔离」由 **锁（当前读）+ MVCC（快照读）** 共同实现；并发问题用「隔离级别 + 间隙锁 + 乐观/悲观锁」组合化解。下一章把这些知识落到 `EXPLAIN` 与慢查询优化上。
