# MySQL 配置管理与运维

> 实例跑得稳不稳，一半看配置、一半看备份与监控。本文覆盖配置文件结构、关键参数、版本升级、备份恢复与四类日志，附常用运维命令。

---

## 1. 配置文件结构

配置文件查找顺序（后生效覆盖前）：`/etc/my.cnf` → `/etc/mysql/my.cnf` → `$MYSQL_HOME/my.cnf` → `~/.my.cnf`。Windows 通常为 `my.ini`。

```ini
[mysqld]            # 服务端配置
[mysqld_safe]       # 安全启动
[client]            # 客户端（mysql/mysqldump 共用）
[mysqldump]
```

核心 `[mysqld]` 片段示例（节选自项目 `配置文件ini.md`）：

```ini
[mysqld]
# 基础
port = 3306
basedir = "C:/Program Files/MySQL/MySQL Server 5.7"
datadir = "C:/ProgramData/MySQL/MySQL Server 5.7/Data"
character-set-server = utf8mb4
default-storage-engine = INNODB
sql-mode = "STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION"

# 连接
max_connections = 151
max_connect_errors = 100
wait_timeout = 28800
interactive_timeout = 28800

# 内存与缓存
innodb_buffer_pool_size = 128M   # 生产调大至物理内存 60%~80%
query_cache_type = 0             # 8.0 已移除查询缓存
thread_cache_size = 10

# 日志
log-output = FILE
general-log = 0
slow-query-log = 1
slow_query_log_file = "DESKTOP-SLOW.log"
long_query_time = 2

# InnoDB 日志
innodb_log_file_size = 48M
innodb_flush_log_at_trx_commit = 1
```

> 8.0 默认字符集已是 `utf8mb4`，无需再显式 `init_connect`；`NO_AUTO_CREATE_USER` 在 8.0 已移除。

---

## 2. 关键参数调优

| 参数 | 建议 | 说明 |
| --- | --- | --- |
| `innodb_buffer_pool_size` | 物理内存 60~80% | 缓存命中率是性能核心 |
| `max_connections` | 按业务峰值 × 2 | 过低报 `Too many connections` |
| `innodb_log_file_size` | 512M~1G | 增大减少 checkpoint 抖动 |
| `innodb_flush_log_at_trx_commit` | 1（强一致）/2（性能） | 见 第 2 章 |
| `sync_binlog` | 1（强一致） | 每事务刷 binlog |
| `thread_cache_size` | 8~32 | 缓存线程，减少创建开销 |
| `max_allowed_packet` | 64M+ | 大批量插入/备份 |

动态修改（无需重启）：

```sql
SET GLOBAL max_connections = 500;
SET PERSIST max_connections = 500;   -- 8.0 持久化到 mysqld-auto.cnf
```

## 3. 版本升级

> 升级前务必**全量备份 + 在测试环境验证**。以 Windows 升级为例（节选自 `升级updata.md`）：

1. 备份数据：`mysqldump -u root -p --all-databases > full.sql`；
2. 停止旧服务：`net stop mysql`；
3. 覆盖安装新版本（选择 "Upgrade" 或保留 data 目录）；
4. 启动后执行升级脚本：`mysql_upgrade -u root -p`（8.0 后 `mysqld --upgrade=AUTO` 自动）；
5. 校验：`SELECT VERSION();`、`SHOW TABLES`。

> 5.7 → 8.0 注意：默认认证插件变化、移除 `query_cache_*`、utf8mb4 为默认，部分旧驱动需更新。

## 4. 备份与恢复

### 4.1 逻辑备份（mysqldump）

```bash
# 单库
mysqldump -u root -p db_name > db.sql
# 全库
mysqldump -u root -p --all-databases > full.sql
# 只导出结构 / 只数据
mysqldump -u root -p -d db > schema.sql     # 结构
mysqldump -u root -p -t db > data.sql        # 数据
```

恢复：

```bash
mysql -u root -p db_name < db.sql
```

### 4.2 物理备份（XtraBackup）

适合大库，热备、速度快、支持增量：

```bash
xtrabackup --backup --target-dir=/backup/full
xtrabackup --prepare --target-dir=/backup/full
xtrabackup --copy-back --target-dir=/backup/full
```

### 4.3 基于 binlog 的增量恢复（PITR）

```bash
mysqlbinlog --start-datetime="2024-01-01 00:00:00" \
            --stop-datetime="2024-01-02 00:00:00" \
            mysql-bin.000001 > restore.sql
```

## 5. 四类日志

| 日志 | 作用 | 关键参数 |
| --- | --- | --- |
| 错误日志 | 启动/运行报错 | `log-error` |
| 慢查询日志 | 定位慢 SQL | `slow_query_log`, `long_query_time` |
| 通用日志 | 全部 SQL（调试用，勿长期开） | `general_log` |
| **binlog** | 复制/恢复/审计 | `log-bin`, `binlog_format=ROW` |

```sql
SHOW BINARY LOGS;
SHOW BINLOG EVENTS IN 'mysql-bin.000001' LIMIT 10;
PURGE BINARY LOGS BEFORE '2024-01-01';   -- 清理旧 binlog
```

## 6. 常用运维命令

```sql
-- 连接/线程
SHOW PROCESSLIST;
SHOW STATUS LIKE 'Threads_connected';
SHOW STATUS LIKE 'Threads_running';

-- 变量
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
SHOW GLOBAL STATUS LIKE 'Innodb_buffer_pool_read%';  -- 算命中率

-- 表/索引
SHOW TABLE STATUS LIKE 'user';          -- 数据/索引大小
SHOW INDEX FROM user;
ANALYZE TABLE user;                     -- 更新统计信息
OPTIMIZE TABLE user;                    -- 回收碎片（InnoDB 重建表）

-- 锁排查
SELECT * FROM information_schema.INNODB_TRX;       -- 活跃事务
SELECT * FROM information_schema.INNODB_LOCK_WAITS; -- 锁等待
```

---

## 7. 监控指标（核心）

- `Threads_connected / max_connections`：连接水位；
- `Innodb_buffer_pool_read_hit`：缓冲命中率（应 > 99%）；
- `Slow_queries`：慢查询数；
- `Innodb_row_lock_waits`：行锁等待；
- `Seconds_Behind_Master`：主从延迟；
- `Created_tmp_disk_tables`：磁盘临时表（排序/分组异常信号）。

## 8. 小结

配置抓「内存/连接/日志」三件大事，运维抓「备份 + 监控 + 锁排查」。至此 MySQL 主线路（安装→引擎→索引→事务→优化→复制→分表→运维）已贯通，最终章以**面试题与实战**收口。
