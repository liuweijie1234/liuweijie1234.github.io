## 一、高频面试题（八股精解）

### 1. MySQL 索引为什么用 B+ 树，不用哈希/B 树？
- B+ 树非叶子节点不存数据 → 单页键多 → 树矮、IO 少；叶子链表 → 范围查询高效；
- 哈希等值快但无法范围、无法排序，且冲突退化；
- B 树非叶存数据导致树更高、范围扫描弱。

### 2. 聚簇索引与二级索引的区别？回表是什么？
主键即聚簇索引，叶子存整行；二级索引叶子存「索引列 + 主键值」，查非索引列需拿主键回聚簇索引取行（**回表**）。用**覆盖索引**可避免。

### 3. 最左前缀原则？
联合索引 `(a,b,c)` 按字典序排序，只能从最左列连续使用。`WHERE b=1` 或 `WHERE a=1 AND c=3`（b 用范围）会导致后续列失效。

### 4. 事务隔离级别？MySQL 默认哪个？
读未提交 / 读已提交 / **可重复读（RR，默认）** / 串行化。RR 下 InnoDB 用 **MVCC 快照读 + Next-Key Lock** 解决幻读。

### 5. MVCC 怎么实现？
`undo log 版本链` + `ReadView`：每行隐藏 `DB_TRX_ID`/`DB_ROLL_PTR`，读时沿版本链找对当前事务可见的版本。RR 复用首次 ReadView（可重复读），RC 每次读新建（不可重复读）。

### 6. redo 和 undo 的区别？
- redo（物理日志）：保证**已提交数据持久性**，崩溃重放；
- undo（逻辑日志）：保证**原子性 + 支持 MVCC 回滚旧版本**。

### 7. 为什么 `LIMIT 100000,10` 慢？怎么优化？
要排序后跳过 10 万行。优化：**延迟关联**（子查询先拿主键再 JOIN 回表）或**游标/书签法**（`WHERE id > last_id LIMIT 10`）。

### 8. 主从延迟怎么排查与解决？
看 `Seconds_Behind_Master`；原因多为从库 SQL 单线程回放不及、大事务、从库重查询。解：并行复制、拆大事务、报表走独立库、读己写走主。

### 9. 如何避免死锁？
固定加锁顺序、缩短事务、降低隔离级别、减小锁范围；InnoDB 自动检测并回滚代价小的事务。

### 10. char 与 varchar 区别？
`char` 定长、补空格，适合短且定长（如 MD5）；`varchar` 变长、省空间但有 1~2 字节长度头，适合不定长文本。

## 二、开篇思考题实战：5000 万订单分页

> 场景：订单表 5000 万行，按时间范围查询并分页 `LIMIT 100000, 10` 很慢，如何优化？

**根因**：`LIMIT offset, n` 先排序再丢弃 offset 行，offset 越大扫描越多。且若 `WHERE` 对 `created` 套了 `DATE()` 函数，索引失效 → 全表扫描。

**优化三连**：

```sql
-- ① 改写日期：去函数，走索引范围
SELECT * FROM orders
WHERE created >= '2024-01-01' AND created < '2024-02-01'
ORDER BY id
LIMIT 100000, 10;   -- 仍慢（offset 大）

-- ② 延迟关联：子查询只扫主键索引，再回表
SELECT a.* FROM orders a
JOIN (
  SELECT id FROM orders
  WHERE created >= '2024-01-01' AND created < '2024-02-01'
  ORDER BY id LIMIT 100000, 10
) b ON a.id = b.id;

-- ③ 游标法（连续翻页，性能恒定）
SELECT * FROM orders
WHERE created >= '2024-01-01' AND created < '2024-02-01'
  AND id > 100000          -- 上一页最后一条 id
ORDER BY id LIMIT 10;
```

> 大表务必让 `ORDER BY` 列有索引，且 `WHERE` 走索引；百万级分页首选**游标/延迟关联**。

## 三、真实工作案例（节选自 `工作/wenzhou.md`）

### 案例 1：按月份统计蓝牙连接数

```sql
SELECT DATE_FORMAT(create_time, '%Y-%m') AS mon, COUNT(*) AS cnt
FROM services_bluetooth
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY mon DESC LIMIT 24;
```

> 注意 `GROUP BY` 表达式需与 `SELECT` 一致，否则结果错乱；大表建议对 `create_time` 建索引或在从库统计。

### 案例 2：本月/上月数据区间

```sql
-- 本月第一天与最后一天
SELECT
  DATE_FORMAT(date_add(curdate(), interval -day(curdate())+1 day), '%Y-%m-%d 00:00:00') AS firstday,
  CONCAT(last_day(curdate()), ' 23:59:59') AS lastday;

-- 上月数据
SELECT * FROM orders
WHERE PERIOD_DIFF(DATE_FORMAT(NOW(),'%Y%m'), DATE_FORMAT(created,'%Y%m')) = 1;
```

### 案例 3：跨模块缺陷统计

```sql
SELECT module, COUNT(*) AS bug_cnt
FROM bugs
GROUP BY module
HAVING COUNT(*) > 10
ORDER BY bug_cnt DESC;
```
