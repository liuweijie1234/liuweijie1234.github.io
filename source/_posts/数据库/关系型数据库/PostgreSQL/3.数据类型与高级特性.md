# PostgreSQL 数据类型与高级特性

Postgres 的「对象关系型」之名，很大程度来自它**丰富且可扩展的数据类型**：除标准 SQL 类型，还内置数组、JSONB、范围、几何、网络等，并支持自定义类型。这让它在「关系 + 半结构化」混合场景游刃有余。本文讲清常用类型与三大高级特性（JSONB / 数组 / 全文检索）。

## 一、基础类型

| 类别 | 类型 |
| --- | --- |
| 数值 | `smallint` `integer` `bigint` `numeric`(精确小数) `real` `double` |
| 字符 | `varchar(n)` `char(n)` `text`（无限长，推荐） |
| 布尔 | `boolean` |
| 日期时间 | `date` `time` `timestamp` `timestamptz`（带时区，推荐） `interval` |
| 二进制 | `bytea` |
| 货币 | `money` |
| 自增 | `serial` / `bigserial`（本质是序列） |

> `numeric(p,s)` 用于金额（精确，避免浮点误差）；`text` 与 `varchar` 性能几乎无差，可放心用 `text`。

## 二、数组（Array）

Postgres 原生支持数组，且可建 GIN 索引：

```sql
CREATE TABLE posts (
  id   serial PRIMARY KEY,
  tags text[]
);

INSERT INTO posts (tags) VALUES (ARRAY['pg','db','sql']);

-- 包含任意元素
SELECT * FROM posts WHERE 'pg' = ANY(tags);
-- 包含全部
SELECT * FROM posts WHERE tags @> ARRAY['pg','sql'];
-- 展开数组
SELECT unnest(tags) FROM posts;
```

应用场景：标签、多值属性、避免「逗号分隔字符串」反模式。

## 三、JSON / JSONB（文档能力）

- `json`：原样存储文本，写入快、查询慢（每次解析）。
- `jsonb`：二进制解析存储，**支持索引、支持包含/存在查询、键顺序无关**——生产首选。

```sql
CREATE TABLE products (
  id    serial PRIMARY KEY,
  attrs jsonb
);

INSERT INTO products (attrs)
VALUES ('{"color":"红","size":"L","price":99}');

-- 提取字段
SELECT attrs->>'color' FROM products;       -- 文本形式
SELECT attrs->'price' FROM products;        -- jsonb 形式

-- 包含查询（键值为）
SELECT * FROM products WHERE attrs @> '{"color":"红"}';
-- 键存在
SELECT * FROM products WHERE attrs ? 'size';
-- 路径提取
SELECT attrs#>>'{price}' FROM products;
```

**JSONB + GIN 索引**实现高效半结构化检索：

```sql
CREATE INDEX idx_attrs ON products USING gin (attrs jsonb_path_ops);
-- 或默认 gin(attrs) 支持 ? 操作符
```

> 这意味着：**同一个 Postgres 既能跑关系查询，又能当文档库用**，无需为了 JSON 引入 MongoDB。

## 四、范围类型（Range）

适合时间段、价格区间：

```sql
CREATE TABLE room_bookings (
  id serial PRIMARY KEY,
  room int,
  during tstzrange
);
INSERT INTO room_bookings (room, during)
VALUES (101, tstzrange('2026-08-01','2026-08-05'));
-- 是否重叠
SELECT * FROM room_bookings WHERE during && tstzrange('2026-08-03','2026-08-10');
```

## 五、全文检索（Full-Text Search）

Postgres 内置强大的全文检索，无需引入 Elasticsearch 即可支撑中小规模搜索：

```sql
CREATE TABLE articles (
  id serial PRIMARY KEY,
  title text,
  body  text,
  tsv   tsvector GENERATED ALWAYS AS (to_tsvector('chinese', title||' '||body)) STORED
);

CREATE INDEX idx_tsv ON articles USING gin(tsv);

-- 检索
SELECT * FROM articles
WHERE tsv @@ to_tsquery('chinese', '数据库 & 索引');
```

- `tsvector`：分词后的文档向量；`tsquery`：查询向量。
- 多种内置词典（english 成熟，chinese 需配合 `zhparser` 插件）。
- 支持权重、排序（`ts_rank`）、短语查询。
- 大规模（亿级）检索仍建议 ES，但中高频场景 Postgres 足以胜任。

## 六、几何与网络类型

- 几何：`point` `line` `polygon` `circle`，配合 PostGIS 可做空间数据库。
- 网络：`inet` `cidr` `macaddr`，适合存 IP、网段。

## 七、自定义类型与扩展

Postgres 的可扩展性是核心优势：

```sql
-- 枚举类型
CREATE TYPE mood AS ENUM ('sad','ok','happy');
-- 复合类型
CREATE TYPE complex AS (r double, i double);
-- 域（带约束的类型）
CREATE DOMAIN pos_int AS integer CHECK (value > 0);
```

常用扩展：

| 扩展 | 能力 |
| --- | --- |
| `postgis` | 地理空间（GIS） |
| `pg_trgm` | 三元组模糊匹配、相似度 |
| `hstore` | 键值对（旧式，现多被 jsonb 取代） |
| `uuid-ossp` | 生成 UUID |
| `pg_stat_statements` | SQL 级性能统计 |
| `citext` | 不区分大小写文本 |

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
SELECT uuid_generate_v4();
```

## 八、与 MySQL 类型对比

| 能力 | PostgreSQL | MySQL |
| --- | --- | --- |
| JSON | ✅ jsonb（强） | ✅ JSON（5.7+） |
| 数组 | ✅ 原生 | ❌ 需逗号串/关系表 |
| 范围 | ✅ | ❌ |
| 全文检索 | ✅ 内置 | 仅 MyISAM 旧 FULLTEXT，弱 |
| 自定义类型 | ✅ | ❌ |
| 严格标准 | ✅ 高度兼容 SQL | 部分兼容 |
