# PostgreSQL 高可用与流复制

Postgres 通过 **WAL 流复制（Streaming Replication）** 实现主从同步，配合故障转移工具（Patroni / repmgr / pgpool）与备份归档，构建高可用集群。本文讲清复制原理、同步/异步、物理/逻辑复制、常见 HA 架构。

## 一、流复制原理

基于 2.的 WAL 机制：Primary 将 WAL 记录通过 TCP 实时**流式**发给 Standby，Standby 重放（redo）到本地，保持与 Primary 一致。

```
  Primary (主)
    │  WAL (wal_sender)
    │  流式推送
    ▼
  Standby (备)
       (wal_receiver → 重放)
```

- Primary 有 `wal_sender` 进程；Standby 有 `wal_receiver` + `startup`（重放）进程。
- Standby 默认**只读**，可分担读流量（类似 MySQL 从库读）。
- 复制延迟通过 `pg_stat_replication` / `pg_stat_wal_receiver` 监控。

## 二、同步 vs 异步

| 模式 | 配置 | 一致性 | 可用性 |
| --- | --- | --- | --- |
| 异步（默认） | `synchronous_commit=on` 仅保证本地 WAL 落盘 | 备可能滞后，故障切换丢最后事务 | 高（主不受备影响） |
| 同步 | `synchronous_standby_names='standby1'` | 主确认备已接收才返回，**零丢失** | 备挂则主写阻塞 |

```ini
# postgresql.conf（主）
synchronous_commit = on
synchronous_standby_names = 'standby1'   # 至少一个同步备

# standby 的 recovery / 新版本 primary_conninfo
primary_conninfo = 'host=primary port=5432 user=replicator'
```

> 同步复制保证强一致但牺牲可用性（CAP 权衡）；多数业务用异步 + 定期备份足矣。

## 三、物理复制 vs 逻辑复制

| 类型 | 粒度 | 特点 |
| --- | --- | --- |
| **物理流复制** | 整个实例（数据块级） | 备库与主完全一致；备可只读；适合 HA/容灾 |
| **逻辑复制** | 表级（行变化） | 可跨版本、跨库、选择性同步；适合多活/ETL/升级迁移 |

逻辑复制基于 **WAL 解码（logical decoding）** + 发布/订阅：

```sql
-- 发布端
CREATE PUBLICATION mypub FOR TABLE users, orders;
-- 订阅端
CREATE SUBSCRIPTION mysub
  CONNECTION 'host=primary dbname=shop user=replicator'
  PUBLICATION mypub;
```

逻辑复制支持跨大版本（如 15→16 升级不停机），是 PG 在线升级的利器。

## 四、搭建流复制（核心步骤）

1. Primary 配置 `wal_level=replica`、`max_wal_senders`、`listen_addresses`。
2. 创建复制账号：`CREATE ROLE replicator WITH REPLICATION LOGIN PASSWORD '...';`
3. `pg_hba.conf` 允许备机复制连接。
4. Standby 用 `pg_basebackup` 从 Primary 拉全量基础备份：
   ```bash
   pg_basebackup -h primary -U replicator -D /var/lib/pgsql/data -P -R
   ```
   `-R` 自动生成 `primary_conninfo` 与 `standby.signal`。
5. 启动 Standby，自动连接 Primary 开始流式接收 WAL。

## 五、高可用架构（HA）

单纯主从不自动故障转移，需 HA 管理组件：

| 工具 | 特点 |
| --- | --- |
| **Patroni** | 基于 DCS（etcd/Consul/ZooKeeper）的 HA 控制器，自动选主/故障转移，业界主流 |
| **repmgr** | 轻量复制管理 + 故障转移 |
| **pgpool-II** | 连接池 + 负载均衡 + 复制（功能多但复杂） |
| **keepalived + VIP** | 简单 VIP 漂移（配 Patroni 更佳） |

典型 Patroni 架构：

```
etcd 集群（3 节点）
   │ 选主依据
   ▼
Patroni(Primary) ←→ Patroni(Standby) ←→ Patroni(Standby)
   │ 故障：etcd 共识 → 新 Primary 被提升 + VIP 漂移
```

## 六、备份与恢复（PITR）

- `pg_basebackup`：物理全量备份。
- 持续归档 WAL（`archive_mode=on` + `archive_command`）到对象存储。
- 结合两者实现 **PITR（时间点恢复）**：恢复到任意历史时刻。

```ini
# postgresql.conf
archive_mode = on
archive_command = 'cp %p /archive/%f'   # 生产用 aws s3 cp 等
```

恢复：用基础备份 + 重放 WAL 到目标时间点（`recovery_target_time`）。

## 七、与 MySQL 复制对比

| 维度 | PostgreSQL 流复制 | MySQL 复制 |
| --- | --- | --- |
| 复制基础 | WAL（物理）/ 逻辑解码 | binlog |
| 默认 | 异步物理流复制 | 异步 binlog |
| 同步复制 | `synchronous_standby_names` | `rpl_semi_sync`（半同步） |
| 逻辑复制 | ✅ 表级发布订阅 | 需 binlog 行格式 + Canal 等 |
| 跨版本复制 | ✅ 逻辑复制支持 | ❌ 要求版本兼容 |
| 故障转移 | 需 Patroni 等 | 需 MHA/MGR/Orchestrator |
