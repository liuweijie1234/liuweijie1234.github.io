# MongoDB 索引原理与优化

索引是 MongoDB 查询性能的根本。没有合适索引，查询会退化为全集合扫描（COLLSCAN）。本文讲清索引底层（B-tree + BSON 排序）、索引类型、最左前缀、覆盖查询与常见失效场景。

## 一、索引底层：B-tree

MongoDB 默认索引 `_id` 和大多数索引基于 **B-tree**（非 B+ 树，叶子节点间无链表）。核心性质：

- 平衡多路搜索树，所有叶子节点等高，查询稳定 O(log n)。
- 索引键按 BSON 比较顺序排序（注意：数字 1 < 字符串，不同类型有固定类型序）。
- 复合索引按字段顺序组合键（如 `{a:1, b:1}` 的键是 `(a, b)`）。

> 与 MySQL InnoDB 的 B+ 树不同：Mongo 的 B-tree 叶子节点直接存**文档指针（Disk Loc / _id）**，聚簇与否取决于是否覆盖。

## 二、索引类型

### 2.1 单字段索引

```javascript
db.users.createIndex({ age: 1 })      // 1=升序，-1=降序（单字段无差别）
```

### 2.2 复合索引（Compound）

```javascript
db.users.createIndex({ city: 1, age: -1 })
```

键按 `(city, age)` 排序，遵循**最左前缀**原则。

### 2.3 多键索引（Multikey，数组索引）

对数组字段建索引，Mongo 自动为每个数组元素建索引项：

```javascript
db.users.createIndex({ tags: 1 })   // tags 是数组，自动多键
```

> 复合索引中**最多一个字段**可以是多键（否则组合爆炸）。

### 2.4 文本索引（Text）

全文检索，支持分词：

```javascript
db.articles.createIndex({ content: "text", title: "text" })
db.articles.find({ $text: { $search: "mongodb 索引" } })
```

### 2.5 地理空间索引（2dsphere / 2d）

```javascript
db.places.createIndex({ loc: "2dsphere" })
db.places.find({ loc: { $near: { $geometry: { type:"Point", coordinates:[116,39] }, $maxDistance: 1000 } } })
```

### 2.6 唯一索引 / 部分索引 / TTL 索引

```javascript
// 唯一
db.users.createIndex({ email: 1 }, { unique: true })

// 部分索引（仅对满足条件建索引，省空间）
db.orders.createIndex({ userId: 1 }, { partialFilterExpression: { status: "PAID" } })

// TTL 索引（自动过期删除，适合日志/会话）
db.sessions.createIndex({ lastActive: 1 }, { expireAfterSeconds: 3600 })
```

### 2.7 通配符索引（Wildcard，4.2+）

对动态/未知字段结构建索引：

```javascript
db.products.createIndex({ "$**": 1 })
```

## 三、最左前缀原则（ESR 法则）

复合索引 `(A, B, C)` 能有效服务以下查询：
- `{A: v}`
- `{A: v, B: w}`
- `{A: v, B: w, C: x}`
- `{A: v, C: x}`（仅用 A 部分，B 跳过后 C 不能走索引范围）

**ESR 排序建议**：Equality（等值）字段在前，Sort（排序）其次，**Range（范围）放最后**。因为范围字段之后的索引列无法再用于精确过滤。

```javascript
// 查询：city=北京 且 age>18 且 按 score 排序
db.users.find({ city: "北京", age: { $gt: 18 } }).sort({ score: -1 })
// 最优索引：{ city: 1, score: -1, age: 1 }  // E(city) S(score) R(age)
```

## 四、覆盖查询（Covered Query）

若查询的过滤字段与返回字段**全部命中同一索引**，Mongo 无需回表读取文档，性能极佳：

```javascript
db.users.createIndex({ city: 1, name: 1 })
// 覆盖：只查 city 过滤、只返回 name
db.users.find({ city: "北京" }, { name: 1, _id: 0 })
```

判断是否覆盖：`explain()` 中 `totalDocsExamined === 0` 且 `stage === "PROJECTION_COVERED"`。

## 五、执行计划分析

```javascript
db.users.find({ city: "北京", age: { $gt: 18 } }).explain("executionStats")
```

关键字段：

| 字段 | 健康值 | 说明 |
| --- | --- | --- |
| `winningPlan.stage` | `IXSCAN` | 索引扫描；`COLLSCAN` 是全表扫描（危险） |
| `totalKeysExamined` | 接近 nReturned | 扫描键数 |
| `totalDocsExamined` | 接近 nReturned | 回表文档数 |
| `executionTimeMillis` | 越小越好 | 耗时 |
| `nReturned` | 实际返回 | — |

> 若看到 `COLLSCAN`，立刻为查询条件建索引；若 `totalDocsExamined >> nReturned`，考虑覆盖索引或调整索引顺序。

## 六、索引的代价与治理

索引不是越多越好：

- **写放大**：每次 insert/update/delete 都要维护所有相关索引。
- **内存占用**：索引需驻留 RAM 才快；索引总量超过内存会频繁换页，性能骤降。
- **磁盘空间**：索引约占数据的 10%~30%。

治理实践：

```javascript
// 查看索引大小
db.users.stats().indexSizes

// 查看冗余/未使用索引（4.2+）
db.users.aggregate([ { $indexStats: {} } ])   // 看 access 次数

// 删除无用索引
db.users.dropIndex({ city: 1 })
```

## 七、索引失效常见场景

1. **隐式类型转换**：`{age: "30"}` 与索引 `{age:1}`（数值）不匹配，退化为全扫。
2. **对字段用函数/运算**：`{ $where: "this.age+1>30" }` 无法用索引。
3. **取反 `$ne` / `$nin`**：通常无法有效利用索引范围（除非高选择性）。
4. **正则 `/^/` 前缀可用，中缀 `/abc/` 不可用**：`{name: /^张/}` 走索引，`{name: /明/}` 不走。
5. **排序与查询索引不匹配**：排序字段不在索引中会导致内存排序（`SORT` stage，超 100MB 报错）。
