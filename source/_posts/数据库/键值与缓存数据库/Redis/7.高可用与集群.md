# Redis 高可用与集群

> 单机 Redis 有容量与单点瓶颈。本文讲清主从复制、哨兵自动故障转移、Cluster 数据分片三种演进形态，以及它们各自解决什么问题。

---

## 1. 主从复制（Replication）

### 作用
- **读写分离**：主写、从读，分摊读压力；
- **数据冗余**：从库是主库的副本，主挂可从顶上；
- **为哨兵/集群奠基**。

### 配置
```bash
# 从库 redis.conf
replicaof 10.0.0.1 6379        # 老版本 slaveof
masterauth <master-password>
replica-read-only yes          # 从库只读
```

### 同步流程
1. **全量同步**：从库首次连接 → 主库 `BGSAVE` 生成 RDB → 传 RDB → 从库加载 → 再补传期间增量命令；
2. **增量同步（命令传播）**：之后主库每有写，异步发给从库；
3. **断线重连**：2.8+ 用 **replication backlog** 做**部分重同步**，只补断开期间的命令，不必全量。

> 主从默认**异步复制**：主写入即返回，从可能短暂落后（可接受最终一致）。

## 2. 哨兵（Sentinel）—— 自动故障转移

主从手动切换太慢，哨兵解决「主挂了自动选新主」。

### 架构
```
      ┌── Sentinel ──┐
Client─┤ Sentinel    ├─ 监控 Master + Replicas
      └── Sentinel ─┘
```
- 多个 Sentinel 互相通信（Quorum 法定人数）；
- 持续 PING 检测主/从存活。

### 故障转移流程
1. **主观下线（SDOWN）**：某 Sentinel 认为主不可达；
2. **客观下线（ODOWN）**：达到 quorum 个 Sentinel 共识主挂了；
3. **选举 Leader Sentinel**：Raft 选一个负责切换；
4. **选新主**：选数据最新、优先级高的从库，执行 `replicaof no one`；
5. **通知/切换**：其他从库 `replicaof` 新主，客户端收到新主地址。

> Sentinel 本身也要部署**奇数个（≥3）** 防脑裂。客户端通过 Sentinel 获取当前主节点地址，勿硬编码 IP。

## 3. Cluster（数据分片）—— 突破单机容量

哨兵解决「高可用」，但不解决**数据量超过单机内存**与**写吞吐上限**。Cluster 用**数据分片**解决。

### 3.1 哈希槽（Hash Slot）

- 共 **16384 个槽**，key 经 `CRC16(key) % 16384` 映射到某槽；
- 槽均匀分配到各**主节点**，节点增减时迁移槽（数据跟着槽走）；
- 客户端可本地缓存槽-节点映射，直连正确节点。

### 3.2 请求重定向
- `MOVED`：槽已迁到别节点，客户端更新映射并重发；
- `ASK`：槽正在迁移中，临时重定向（不更新映射）。

### 3.3 配置（至少 3 主 3 从）
```bash
# 各节点
cluster-enabled yes
cluster-node-timeout 5000

# 建集群（6 节点）
redis-cli --cluster create \
  10.0.0.1:6379 10.0.0.2:6379 10.0.0.3:6379 \
  10.0.0.4:6379 10.0.0.5:6379 10.0.0.6:6379 \
  --cluster-replicas 1
```

### 3.4 限制与注意
- **不支持多 key 跨槽事务**（除非用 hash tag 把它们绑到同一槽，如 `user:{100}:name`、`user:{100}:age`）；
- 读写命令仍单线程，Cluster 提升的是**容量与节点级并发**，单 key 操作性能不变；
- 槽迁移期间部分请求被 `ASK` 重定向，属正常。

---

## 4. 三种形态对比

| 形态 | 解决问题 | 不足 |
| --- | --- | --- |
| 主从 | 读扩展、数据冗余 | 主挂需手动切 |
| 哨兵 | 自动故障转移（高可用） | 不解决容量上限 |
| Cluster | 数据分片（容量+写扩展）+ 高可用 | 跨槽限制、运维复杂 |

---

## 5. 选型建议

- 数据量小、要省心：**主从 + 哨兵**；
- 数据超大/需水平扩展：**Cluster**；
- 纯缓存且可丢：单机 + 多实例即可，不必上集群。

---

## 6. 小结

从主从（冗余/读扩展）→ 哨兵（自动切换）→ Cluster（分片扩展），Redis 的高可用与扩展路径清晰。下一章 **内存管理与过期淘汰** 讲「内存怎么省、Key 怎么清、大 Key 怎么治」。
