# Redis 内存管理与过期淘汰

> Redis 是内存数据库，「内存用满」是头号运维问题。本文讲清 Key 过期机制、内存淘汰策略、大/热 Key 治理与碎片优化，避免 OOM 与卡顿。

---

## 1. Key 过期机制

`EXPIRE/PEXPIRE` 给 key 设 TTL。Redis 用**两种策略**清理过期 key：

### 1.1 惰性删除（Lazy）
访问 key 时才检查是否过期，过期则删。优点：零额外开销；缺点：冷 key 一直占内存。

### 1.2 定期删除（Active）
每隔一段时间（默认 100ms，10 次/秒）**随机抽样**一部分 key，删除其中过期的。通过 `hz` 控制频率。

> 二者结合：惰性保证「访问即清」，定期保证「后台兜底」，避免大量冷过期 key 堆积。

---

## 2. 内存淘汰策略（maxmemory 触发）

当内存达 `maxmemory`，新写入触发**淘汰**（`noeviction` 除外直接报错）。策略：

| 策略 | 行为 |
| --- | --- |
| `noeviction`（默认） | 不淘汰，写报错（OOM） |
| `allkeys-lru` | 所有 key 中淘汰**最近最少用** |
| `volatile-lru` | 仅设了 TTL 的 key 中 LRU |
| `allkeys-lfu`（4.0+） | 所有 key 中淘汰**最不常使用**（频率） |
| `volatile-lfu` | 仅 TTL key 中 LFU |
| `allkeys-random` | 随机淘汰 |
| `volatile-random` | 仅 TTL key 随机 |
| `volatile-ttl` | 淘汰 TTL 最短的 |

```ini
maxmemory 2gb
maxmemory-policy allkeys-lru
```

> **LRU vs LFU**：LRU 看「多久没用」，LFU 看「用得频次」，LFU 更抗偶发热点误淘汰，4.0+ 推荐 `allkeys-lfu`。

## 3. 内存碎片

`info memory` 中关注：
```
used_memory            # Redis 实际申请内存
used_memory_rss        # 操作系统分配（含碎片）
mem_fragmentation_ratio = rss / used_memory
```
- 比值 **>1.5**：碎片严重（频繁删大对象、小对象分配）；
- 解决：`activedefrag yes` 开启**主动碎片整理**，或重启重建。

---

## 4. 大 Key 治理

**定义**：value 过大或元素过多的 key（如 10MB 的 String、百万 field 的 Hash）。

### 危害
- 删除/迁移阻塞单线程（同步释放大对象耗时）；
- 网络带宽被一次传输打满；
- Cluster 迁移槽时卡住。

### 排查
```bash
redis-cli --bigkeys          # 扫描统计各类型最大 key
DEBUG OBJECT key             # 看编码与元素数（谨慎）
```

### 解决
- **拆分**：大 Hash 按 field 取模分片成多个小 key；
- **分批删除**：用 `UNLINK`（异步删，4.0+，非阻塞）替代 `DEL`；
- **压缩**：String 用压缩算法（如 gzip）再存。

---

## 5. 热 Key 治理

**定义**：被超高并发访问的单个 key，使所在节点 CPU/网络打满。

### 发现
- 监控 `hotkey`（Redis 7.0 `redis-cli --hotkeys`）；
- 代理层（Twemproxy/Cluster 客户端）统计访问频率。

### 解决
- **本地缓存**：应用层用 Caffeine/Guava 缓存热 key 副本，分散请求；
- **分散打散**：key 加随机后缀（如 `hotkey:{0..9}`），请求均摊到多节点，读时聚合并写回；
- **限流**：对热 key 访问做令牌桶限流。

---

## 6. 内存使用优化

- 小数据用 `ziplist/listpack`（紧凑编码），调大 `hash-max-ziplist-entries` 阈值让更多元素走紧凑结构；
- 用 **Hash/Zip 结构** 批量存字段，而非大量独立 String（节省 redisObject 开销）；
- 给缓存设合理 TTL，避免冷数据常驻；
- 避免存大 JSON/大对象，拆小。

---

## 7. 小结

内存管理三板斧：**过期（惰性+定期）清冷 key、淘汰策略保写可用、大/热 Key 治理保稳定**。至此 Redis 主线（安装→类型→为什么快→持久化→缓存→锁/队列→高可用→内存）贯通，最后一章做**对比与实战**收口。
