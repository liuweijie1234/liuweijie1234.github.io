# Redis 与 Memcached 对比及实战

> 同为内存 KV 缓存，为什么现在几乎一边倒选 Redis？本文给出硬核对比，并总结 Redis 的工程实战场景与最佳实践。

---

## 1. Redis vs Memcached

| 维度 | Redis | Memcached |
| --- | --- | --- |
| 线程模型 | 单线程命令执行 + 6.0 IO 多线程 | **多线程**（原生） |
| 数据类型 | 5 种基础 + Bitmap/HLL/GEO/Stream | 仅 String |
| 值大小 | 最大 512MB | 单条通常 ≤ 1MB |
| 持久化 | RDB / AOF（可落盘） | 纯内存，重启即丢 |
| 高可用 | 主从 / 哨兵 / Cluster | 无原生集群，靠客户端一致性哈希 |
| 发布订阅 | 支持 | 不支持 |
| Lua 脚本 | 支持（原子复杂操作） | 不支持 |
| 事务 | 支持（MULTI/EXEC） | 不支持 |
| 内存管理 | 灵活编码 + 淘汰策略 | slab 预分配，可能有碎片 |
| 典型场景 | 缓存 + 队列 + 锁 + 存储 | 纯高并发简单缓存 |

> 结论：Memcached 仅适合「极简 String 缓存 + 超高并发纯读」；Redis 因数据结构丰富、功能全面，几乎通吃缓存、锁、队列、排行榜等场景，是现代首选。

---

## 2. Redis 的特点与优势

- **极快**：内存 + 单线程无锁 + IO 多路复用；
- **数据结构丰富**：一套搞定计数、排行、去重、队列；
- **持久化可选**：兼顾缓存速度与数据安全；
- **高可用/分布式**：主从、哨兵、Cluster 成熟；
- **生态完整**：客户端多、运维工具全、云托管普及。

## 3. 实战场景速查

| 场景 | 用法 | 类型/命令 |
| --- | --- | --- |
| 缓存 | 热点数据前置 DB | String + TTL + Cache-Aside |
| 分布式锁 | 互斥协调 | `SET NX EX` + Lua 释放 |
| 计数器 | 播放量/点赞 | `INCR`/`INCRBY` |
| 排行榜 | 游戏/销量榜 | `ZADD`/`ZREVRANGE` |
| 限流 | 接口防刷 | `INCR`+`EXPRIE` 或令牌桶 |
| 会话存储 | 登录 Session | String/Hash + TTL |
| 消息队列 | 异步解耦 | List `LPUSH/BRPOP` 或 Stream |
| 延迟任务 | 订单超时关单 | ZSet（score=执行时间） |
| 共同好友 | 社交关系 | Set `SINTER` |
| 签到/在线 | 位统计 | Bitmap `SETBIT/BITCOUNT` |
| UV 统计 | 省内存计数 | HyperLogLog `PFADD/PFCOUNT` |
| 附近的人 | 地理位置 | GEO |

## 4. 接口限流实战（计数器法）

```bash
# 每秒最多 100 次
key = "ratelimit:ip:1.2.3.4:" + (当前秒)
count = INCR key
IF count == 1 THEN EXPIRE key 1
IF count > 100 THEN return "限流"
```

> 更平滑用**滑动窗口 / 令牌桶**，可借助 Redis + Lua 原子实现。

## 5. 排行榜实战

```bash
ZADD game:rank 9500 playerA
ZADD game:rank 10200 playerB
ZREVRANGE game:rank 0 9 WITHSCORES    # Top10
ZRANK game:rank playerA               # 名次
```

## 6. 订单超时关闭（延迟队列）

```bash
# 下单时
ZADD order:delay <下单时间+30min> orderId
# 定时任务扫描到期
due = ZRANGEBYSCORE order:delay 0 <now> LIMIT 0 100
for orderId in due:
    if 未支付: 关单
    ZREM order:delay orderId
```

## 7. 最佳实践总结

1. **缓存都设 TTL**，防冷数据常驻与雪崩；
2. **Key 命名规范**：`业务:对象:id:字段`，如 `user:1001:name`；
3. **避免大 Key / 热 Key**（见 第 8 章）；
4. **批量用 Pipeline / MGET**，减少 RTT；
5. **锁/队列用 Lua 保原子**；
6. **生产必上高可用**（哨兵/Cluster），勿裸跑单机；
7. **监控**：命中率、内存、连接数、慢命令、大 Key。
