# Nginx 反向代理与负载均衡

Nginx 通过 `proxy_pass` 将请求转发到后端服务，并结合 `upstream` 实现负载均衡，是生产环境最常见的网关形态。

## 反向代理（proxy_pass）

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> `proxy_pass` 后若带 URI（如 `http://backend/`），会替换 `location` 匹配到的部分；不带 URI 则原样透传路径。

## 负载均衡策略

在 `upstream` 中定义后端池，默认轮询：

```nginx
upstream backend {
    # 默认轮询
    server 10.0.0.1:8080 weight=3;   # 加权轮询，权重越大分配越多
    server 10.0.0.2:8080;
    server 10.0.0.3:8080 backup;     # 备机，主全挂才启用
    server 10.0.0.4:8080 down;       # 临时下线
    # ip_hash;                       # 按客户端 IP 哈希，保证会话粘滞
    # least_conn;                    # 转发给连接数最少的节点
}
```

| 策略 | 说明 | 适用场景 |
| --- | --- | --- |
| 轮询（默认） | 依次分发 | 后端无状态、性能一致 |
| `weight` | 加权轮询 | 机器配置不均 |
| `ip_hash` | 同 IP 固定到同一节点 | 需要会话保持 |
| `least_conn` | 最少连接优先 | 请求耗时差异大 |
| `hash $request_uri` | 按 URI 哈希 | 缓存命中优化 |

> 会话保持的更优解是后端共享 Session（Redis）或用 `ip_hash`/第三方 `sticky` 模块。

## 健康检查与故障转移

Nginx Plus 支持主动健康检查；开源版通过被动检测实现故障转移：

```nginx
upstream backend {
    server 10.0.0.1:8080 max_fails=3 fail_timeout=30s;
    server 10.0.0.2:8080 max_fails=3 fail_timeout=30s;
}
```

- `max_fails`：在 `fail_timeout` 内允许的最大失败次数，超过则暂时摘除该节点。
- `fail_timeout`：节点被标记为不可用的时间，到期自动重试。

## 动静分离与缓存

```nginx
# 静态资源直出
location ~* \.(jpg|css|js|png)$ {
    root /data/static;
    expires 30d;          # 客户端缓存 30 天
    access_log off;
}

# 代理接口并开启缓存
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:10m max_size=1g;
location /api/ {
    proxy_cache api_cache;
    proxy_cache_valid 200 10m;
    proxy_pass http://backend;
}
```

## WebSocket 透传

```nginx
location /ws/ {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

## 限流（limit_req）

```nginx
http {
    limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;
    server {
        location /api/ {
            limit_req zone=one burst=20 nodelay;  # 突发 20，立即处理
            proxy_pass http://backend;
        }
    }
}
```

## 完整示例

```nginx
upstream app {
    least_conn;
    server 10.0.0.1:8080 weight=2;
    server 10.0.0.2:8080;
}

server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
