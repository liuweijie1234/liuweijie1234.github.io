# 负载均衡与网关

负载均衡（Load Balancing）将流量分发到多个后端，提升吞吐、可用性与扩展性；网关则在此基础上提供统一的接入治理。

## 负载均衡层级

| 层级 | 工作位置 | 代表 | 特点 |
| --- | --- | --- | --- |
| **L4（四层）** | 传输层（IP + 端口） | LVS、硬件 F5、云 NLB | 性能好、不解析内容、按连接/源 IP 分发 |
| **L7（七层）** | 应用层（HTTP/HTTPS） | Nginx、HAProxy、API 网关 | 可按 URL/Header/Cookie 路由、改写、限流 |

## LVS（IPVS）原理与模式

LVS 基于内核 IPVS，是高性能 L4 负载均衡：

- **NAT 模式**：请求与响应都经 Director（Director 成瓶颈，后端可私网）。
- **DR（Direct Routing）模式**：仅请求经 Director，响应直接回客户端（性能最佳，要求同 VLAN）。
- **TUN（IP 隧道）模式**：Director 与 RS 跨网段，IP 封装转发。

```bash
# 查看 IPVS 规则
ipvsadm -Ln

# 添加虚拟服务与真实服务器（DR 模式示例）
ipvsadm -A -t 10.0.0.100:80 -s rr
ipvsadm -a -t 10.0.0.100:80 -r 10.0.0.1:80 -g
ipvsadm -a -t 10.0.0.100:80 -r 10.0.0.2:80 -g
```

调度算法：`rr`（轮询）、`wrr`（加权）、`lc`（最少连接）、`sh`（源哈希）。

## HAProxy 配置与场景

HAProxy 是成熟的高性能 L4/L7 负载均衡与代理：

```haproxy
frontend http-in
    bind *:80
    default_backend web

backend web
    balance roundrobin
    option httpchk GET /healthz
    server s1 10.0.0.1:8080 check
    server s2 10.0.0.2:8080 check
```

- 健康检查：`check`、`inter`、`rise`/`fall`。
- 模式：`mode tcp`（L4）/ `mode http`（L7，可基于路径/Host 路由）。
- 统计页面：`stats enable`，可观察各后端状态。
- 重载：`systemctl reload haproxy`（无中断）。

## API 网关概念

API 网关在 L7 之上提供统一接入治理：

- **鉴权**：JWT/OAuth2/API Key，统一校验。
- **限流**：令牌桶、漏桶，保护后端。
- **路由**：按路径/版本转发到对应服务。
- **灰度/金丝雀**：按权重或 Header 分流。
- **可观测**：统一日志、指标、链路追踪。

常见选型：**Kong**、**APISIX**（云原生、高性能）、**Spring Cloud Gateway**（Java 生态），以及 K8s 的 **Ingress Controller**（ingress-nginx、Traefik）。

## 与 Nginx / Ingress 的关系

- **Nginx**：既做 Web 服务器，也做 L7 负载均衡与前反向代理，轻量通用（见 [Nginx 反向代理与负载均衡](Nginx/反向代理与负载均衡.md)）。
- **HAProxy**：专业的 L4/L7 负载均衡，适合大流量入口。
- **LVS**：L4 内核级，性能极致，常作最外层。
- **Ingress（K8s）**：Kubernetes 内的 L7 路由（见 [Kubernetes Service 与 Ingress](../容器与编排/Kubernetes/Service与Ingress.md)）。
- 典型链路：客户端 → LVS/F5（L4）→ HAProxy/Nginx（L7）→ 应用；云上则常用 SLB/ALB + Ingress。

选型建议：单站点/简单代理用 Nginx；高并发 L4 用 LVS/云 NLB；丰富路由与治理用网关（Kong/APISIX）；K8s 内用 Ingress。
