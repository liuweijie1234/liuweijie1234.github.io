# Kubernetes 核心概念与架构

Kubernetes（K8s）是容器编排的事实标准，负责容器化应用的调度、伸缩、服务发现与自愈。理解其架构与对象模型是运维 K8s 的前提。

## 集群架构

K8s 集群由**控制平面（Control Plane）**与**工作节点（Node）**组成：

- **Control Plane（Master）**：集群大脑。
  - `kube-apiserver`：唯一入口，所有组件通过它通信。
  - `etcd`：分布式键值存储，保存集群全部状态（唯一数据源）。
  - `kube-scheduler`：将 Pod 调度到合适节点。
  - `kube-controller-manager`：运行各类控制器（副本、节点、端点等），维持期望状态。
  - `cloud-controller-manager`：对接云厂商（可选）。
- **Node（工作节点）**：
  - `kubelet`：节点代理，管理本节点的 Pod 生命周期。
  - `kube-proxy`：维护节点网络规则（Service 的 iptables/IPVS）。
  - **容器运行时**：如 containerd、CRI-O，真正运行容器。

```
      +------------------- 控制平面 -------------------+
      |  kube-apisneer  |  etcd  |  scheduler | cm   |
      +------------------------------------------------+
                   |  (API)          | (心跳/状态)
        +------------------+      +------------------+
        | Node1: kubelet   |      | Node2: kubelet   |
        | kube-proxy 容器运行时 |      | kube-proxy 容器运行时 |
        +------------------+      +------------------+
```

## 对象模型（Object / Spec / Status）

- 所有资源都是**对象**，通过 `kubectl` 或 YAML 声明。
- **Spec（期望状态）**：用户定义的目标状态。
- **Status（实际状态）**：系统观测到的当前状态，控制器持续将 Status 收敛到 Spec。

```bash
kubectl get all -n default          # 查看默认命名空间资源
kubectl describe pod <pod>          # 查看详情与事件（排障首选）
kubectl api-resources              # 列出所有资源类型
kubectl explain deployment.spec    # 查看某字段的 API 文档
```

## 命名空间（Namespace）与资源配额

Namespace 用于逻辑隔离资源（多环境/多团队）：

```bash
kubectl get ns
kubectl create ns staging
kubectl get pods -n staging

# 资源配额（限制某命名空间可使用的 CPU/内存）
kubectl create quota my-quota -n staging --hard=cpu=4,memory=8Gi,pods=20
```

## 声明式 vs 命令式

- **声明式（推荐）**：`kubectl apply -f xxx.yaml`，系统计算差异并应用，可重复执行、可版本化。
- **命令式**：`kubectl create / run / expose`，一次性操作，难以追溯。

生产统一使用声明式 YAML + Git 管理（`kubectl apply -k` 或配合 ArgoCD/GitOps）。

## 高可用控制平面

- 生产应将 Master 组件多副本（至少 3 个，配负载均衡）。
- `etcd` 集群奇数节点（3/5），独立部署并定期备份。
- `kube-apiserver`、`controller-manager`、`scheduler` 均支持多实例（active-active 或 leader 选举）。
