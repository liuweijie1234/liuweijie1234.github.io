# Kubernetes 配置与存储

K8s 通过 ConfigMap / Secret 管理配置，通过 Volume / PV / PVC 管理存储，实现配置与镜像解耦、数据持久化。

## ConfigMap（配置注入）

用于非敏感的配置（如配置文件、环境变量）：

```bash
# 从文件创建
kubectl create configmap app-config --from-file=app.conf

# 从字面量创建
kubectl create configmap app-config --from-literal=LOG_LEVEL=info --from-literal=PORT=8080
```

在 Pod 中引用：

```yaml
spec:
  containers:
  - name: web
    env:
    - name: LOG_LEVEL
      valueFrom:
        configMapKeyRef: { name: app-config, key: LOG_LEVEL }
    volumeMounts:
    - name: cfg
      mountPath: /etc/app
  volumes:
  - name: cfg
    configMap:
      name: app-config
```

## Secret（敏感信息）

用于存储密码、Token、证书等（base64 编码，**非加密**，需配合 RBAC 与加密 at-rest）：

```bash
kubectl create secret generic db-secret --from-literal=password=xxx
kubectl create secret tls example-tls --cert=fullchain.pem --key=privkey.pem
```

引用方式与 ConfigMap 类似（`secretKeyRef` / `secret` 卷）。建议启用 etcd 静态加密，并使用外部密钥管理（Vault、云 KMS）。

> ConfigMap vs Secret：Secret 面向敏感数据，有额外限制（如不能用于 `imagePullPolicy` 之外部分场景），本质都是键值对。

## 存储卷（Volume / PV / PVC）

- **Volume**：Pod 内的存储抽象，生命周期与 Pod 一致（emptyDir 随 Pod 删除）。
- **PV（PersistentVolume）**：集群级存储资源（由管理员或 StorageClass 动态供给）。
- **PVC（PersistentVolumeClaim）**：用户对存储的请求，K8s 自动绑定到合适的 PV。

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data-pvc }
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests: { storage: 10Gi }
  storageClassName: standard
---
apiVersion: apps/v1
kind: Deployment
spec:
  template:
    spec:
      containers:
      - name: db
        volumeMounts:
        - { name: data, mountPath: /var/lib/mysql }
      volumes:
      - name: data
        persistentVolumeClaim: { claimName: data-pvc }
```

```bash
kubectl apply -f pvc.yaml
kubectl get pvc           # 状态变为 Bound 即绑定成功
kubectl get pv
```

## StorageClass 与动态供给

StorageClass 定义了 PV 的"供应模板"，PVC 指定 `storageClassName` 后由 Provisioner 自动创建 PV，无需预分配：

```bash
kubectl get storageclass
# 设为默认
kubectl patch storageclass standard -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
```

常见 Provisioner：云厂商盘（AWS EBS、阿里云云盘）、Ceph RBD、NFS、local-volume。

## 配置热更新与挂载

- 以 `subPath` 挂载的 ConfigMap 不会自动更新；完整卷挂载会在 ConfigMap 变更后（有同步延迟）自动更新文件内容，但需应用自行 reload。
- 滚动重启以应用新配置：`kubectl rollout restart deployment/web`。
- 敏感配置变更建议走 Secret 重建 + 滚动更新，避免明文残留。

## 排障

```bash
kubectl describe pvc data-pvc     # 查看为何未 Bound
kubectl get events --sort-by=.lastTimestamp
kubectl exec -it web -- df -h     # 确认挂载点
```
