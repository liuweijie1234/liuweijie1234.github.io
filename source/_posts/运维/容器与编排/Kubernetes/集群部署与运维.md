# Kubernetes 集群部署与运维

本章覆盖 K8s 集群的搭建、节点管理、升级备份与日常排障。

## 部署方式选型

| 方式 | 说明 | 适用 |
| --- | --- | --- |
| `kubeadm` | 官方工具，半自动搭建生产可用集群 | 自建集群（推荐） |
| 二进制 | 手动部署各组件，灵活但繁琐 | 深度定制/离线 |
| 托管服务 | EKS / ACK / GKE / TKE | 不想运维控制平面 |
| k3s / kind / minikube | 轻量/本地 | 边缘/开发测试 |

## 使用 kubeadm 搭建集群

**前置**：所有节点禁用 swap、加载 `br_netfilter`、配置容器运行时（containerd）。

```bash
# 控制平面初始化（Flannel 用 10.244.0.0/16）
kubeadm init --pod-network-cidr=10.244.0.0/16 --kubernetes-version=1.30.0

# 配置 kubectl（master 上）
mkdir -p $HOME/.kube
cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
chown $(id -u):$(id -g) $HOME/.kube/config

# 工作节点加入（init 后输出）
kubeadm join 192.168.1.10:6443 --token xxx --discovery-token-ca-cert-hash sha256:yyy

# 安装网络插件（CNI，如 Flannel）
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
kubectl get nodes          # 全部 Ready
```

## 高可用 Master

- 至少 3 个 Master 节点 + 独立 etcd（3/5 节点）或堆叠 etcd。
- `kubeadm init --control-plane-endpoint <VIP>:6443 --upload-certs` 支持多控制平面。
- 前端用 HAProxy/Keepalived 或云 LB 暴露 6443。

## 节点管理与污点（taint）/容忍（toleration）

```bash
kubectl cordon node-1          # 标记为不可调度（排水前）
kubectl drain node-1 --ignore-daemonsets --delete-emptydir-data   # 驱逐 Pod
kubectl uncordon node-1         # 恢复调度

# 给节点打污点，禁止普通 Pod 调度
kubectl taint nodes node-1 dedicated=true:NoSchedule
```

Pod 通过 `tolerations` 容忍对应污点（如专用 GPU 节点）。

## 集群升级

```bash
# 控制平面（逐节点升级）
kubeadm upgrade plan
kubeadm upgrade apply v1.31.0
# 工作节点：kubeadm upgrade node，再 kubelet 升级
```

升级遵循"先控制平面、后节点、逐节点 drain/uncordon"原则，注意跨版本不跳版。

## 备份与恢复（etcd 快照）

etcd 是集群唯一状态源，必须定期备份：

```bash
# 备份
ETCDCTL_API=3 etcdctl snapshot save snap.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# 恢复（停止 kube-apiserver 后）
ETCDCTL_API=3 etcdctl snapshot restore snap.db --data-dir=/var/lib/etcd-restore
```

## 常用排障

```bash
kubectl get events --sort-by=.lastTimestamp   # 集群事件
kubectl describe pod <pod>                     # 调度/拉镜像失败原因
kubectl logs <pod> -c <container>              # 容器日志
kubectl logs <pod> --previous                  # 上一次崩溃日志
kubectl exec -it <pod> -- sh                   # 进容器
kubectl debug node/node-1 -it --image=busybox  # 节点排障（Ephemeral 容器）
kubectl get componentstatuses                  # 控制平面组件健康
journalctl -u kubelet -f                       # 节点 kubelet 日志
```

## 资源监控与扩缩容（HPA）

```bash
# 部署 metrics-server 后方可使用 HPA
kubectl top nodes
kubectl top pods

# 基于 CPU 自动扩缩（需设置 resources.requests）
kubectl autoscale deployment web --cpu-percent=70 --min=2 --max=10
kubectl get hpa
```
