# Linux 用户与权限

用户与权限是 Linux 安全的基础，涉及账号管理、文件权限、提权与强制访问控制。

## 用户与用户组

```bash
useradd -m -s /bin/bash alice          # 创建用户并生成家目录
useradd -M -s /sbin/nologin app        # 系统/服务用户（无登录）
passwd alice                            # 设置密码
usermod -aG sudo alice                  # 追加到 sudo 组（-a 避免覆盖）
usermod -s /bin/zsh alice               # 修改登录 shell
userdel -r alice                        # 删除用户并删家目录
groupadd dev                            # 建组
groups alice                            # 查看用户所属组
id alice                                # 查看 uid/gid
```

- uid 0 为 root；系统用户 uid 通常 < 1000。

## 文件权限（rwx / chmod / chown / umask）

权限位：`r` 读(4)、`w` 写(2)、`x` 执行(1)，分属**所有者/所属组/其他**：

```bash
ls -l file.conf
# -rw-r----- 1 app app 1234 Jul 30 10:00 file.conf
chmod 640 file.conf        # 属主读写、属组读、其他无
chmod u+x script.sh        # 仅给属主加执行位
chown app:app file.conf    # 改属主与属组
chown -R app:app /data     # 递归
umask 022                  # 新建文件默认权限 = 666-umask，目录 = 777-umask
```

### 特殊权限位

- **SUID（4）**：执行时以文件属主身份运行（如 `passwd`）。
- **SGID（2）**：目录中新建文件继承目录属组；可执行文件以属组身份运行。
- **Sticky（1）**：目录中仅文件属主可删（如 `/tmp`）。

```bash
chmod 4755 /usr/bin/somecmd     # SUID
chmod 1777 /shared              # Sticky
```

## sudo 与提权（/etc/sudoers）

```bash
# 编辑（必须用 visudo 校验语法）
visudo
# 允许 alice 无需密码执行特定命令
alice ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx
# 允许 dev 组执行全部命令（需密码）
%dev ALL=(ALL) ALL
```

- 永远用 `visudo` 编辑，语法错误会导致无法提权。
- 遵循最小权限：只授权必要命令，避免直接 `NOPASSWD: ALL`。

## ACL 访问控制（setfacl / getfacl）

标准 ugo 权限不够细时，用 ACL 给特定用户/组单独授权：

```bash
setfacl -m u:bob:rwx /data/share     # 给 bob 单独 rwx
setfacl -m g:dev:rx  /data/share     # 给 dev 组 rx
getfacl /data/share                  # 查看 ACL
setfacl -b /data/share               # 清除 ACL
```

## SELinux / AppArmor 基础

- **SELinux**（RHEL/CentOS 默认）：基于标签的强制访问控制。
  ```bash
  getenforce                  # 查看模式（Enforcing/Permissive/Disabled）
  setenforce 0               # 临时改为 Permissive（排障）
  ls -Z file                 # 查看安全上下文
  semanage fcontext -a -t httpd_sys_content_t "/data/www"  # 改上下文
  restorecon -Rv /data/www
  ```
- **AppArmor**（Ubuntu/Debian 默认）：基于路径的 MAC，配置更简单。
  ```bash
  aa-status                  # 查看状态
  aa-enforce /etc/apparmor.d/usr.sbin.nginx
  ```
- 排障：访问被拒但权限正确时，多半是 SELinux/AppArmor 拦截，查 `/var/log/audit/audit.log` 或 `dmesg`。

## 密钥登录与 SSH 安全

```bash
# 生成密钥并分发
ssh-keygen -t ed25519
ssh-copy-id alice@host

# 服务端加固 /etc/ssh/sshd_config
PermitRootLogin no          # 禁止 root 直登
PasswordAuthentication no   # 仅密钥登录
Port 2222                   # 改默认端口（配合防火墙）
AllowUsers alice bob        # 白名单
systemctl restart sshd
```

- 私钥权限须为 `600`，否则 ssh 拒绝使用。
- 多机管理可用 `ssh-agent` 或配置 `~/.ssh/config`。
