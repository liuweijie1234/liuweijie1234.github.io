# Elasticsearch 安装部署

Elasticsearch 是分布式的搜索与分析引擎，是 ELK 的存储与检索核心。以下为单节点/集群的基础部署。

## 前置准备

```bash
# 1. 安装 JDK（ES 7+ 自带 JDK，可跳过；8.x 需 JDK 17）
java -version

# 2. 调整系统参数
# 禁用 swap
swapoff -a
# 设置 vm.max_map_count（ES 要求 ≥ 262144）
sysctl -w vm.max_map_count=262144
# 文件描述符上限
ulimit -n 65535
```

编辑 `/etc/security/limits.conf`：

```
elasticsearch soft nofile 65535
elasticsearch hard nofile 65535
```

## 安装（RPM 方式）

```bash
# 导入 GPG 与仓库
rpm --import https://artifacts.elastic.co/GPG-KEY-elasticsearch
cat > /etc/yum.repos.d/elasticsearch.repo <<'EOF'
[elasticsearch]
name=Elasticsearch repository
baseurl=https://artifacts.elastic.co/packages/8.x/yum
gpgcheck=1
gpgkey=https://artifacts.elastic.co/GPG-KEY-elasticsearch
enabled=1
EOF
yum install -y elasticsearch
```

## 关键配置（elasticsearch.yml）

```yaml
cluster.name: my-es
node.name: node-1
path.data: /var/lib/elasticsearch
path.logs: /var/log/elasticsearch
network.host: 0.0.0.0
http.port: 9200
discovery.seed_hosts: ["10.0.0.1", "10.0.0.2", "10.0.0.3"]
cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]
xpack.security.enabled: true        # 生产务必开启安全
```

> 单节点开发可设 `discovery.type: single-node`，跳过选主。

## 启动

```bash
systemctl enable --now elasticsearch
# 等待启动，验证
curl -u elastic:password http://localhost:9200
```

返回集群信息 JSON 即成功。

## 安全与密码（8.x）

8.x 默认开启安全，首次启动会在日志打印 `elastic` 用户初始密码；也可重置：

```bash
/usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic
```

配置 Kibana/Logstash 连接时填入该凭据（或创建专用用户并赋权）。

## 集群与分片规划

- **索引**：数据逻辑单元；**分片（shard）**：索引的水平切片，可分布到多节点实现并行与扩容；**副本（replica）**：分片拷贝，提供高可用与读扩展。
- 建议单分片大小控制在 10–50 GB；副本数按可用性需求设 1（至少）。
- 节点角色：master（选主）、data（存数据）、ingest（预处理）、coordinating（协调节点）。

## 常用运维命令

```bash
# 集群健康
curl -u elastic:password localhost:9200/_cluster/health?pretty
# 节点列表
curl localhost:9200/_cat/nodes?v
# 索引列表与大小
curl localhost:9200/_cat/indices?v
# 创建/删除索引
curl -X PUT localhost:9200/logs-2026
curl -X DELETE localhost:9200/logs-old
```

更多命令见 [Elasticsearch 常用命令](常用命令.md)；可视化见 [Kibana 常用命令](../Kibana/常用命令.md)。

## 排障

- 启动失败先看 `/var/log/elasticsearch/` 与 `journalctl -u elasticsearch`。
- `max virtual memory areas vm.max_map_count [65530] is too low` → 调整 `vm.max_map_count`。
- 脑裂：8.x 默认使用 `*_coordinator` 与票选机制，确保 `initial_master_nodes` 正确。
- 磁盘水位：默认 `85%` 只读、`90%` 拒写，需扩容或清理索引。
